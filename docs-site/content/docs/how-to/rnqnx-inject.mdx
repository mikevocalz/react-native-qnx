---
title: Drive input with rnqnx-inject
description: Build rnqnx-inject, copy it to the Pi, and send pointer, wheel and key events through QNX Screen from a script over ssh, including held keys with auto-repeat.
---

`rnqnx-inject` sends pointer and keyboard events through QNX Screen the way a USB mouse and keyboard do, so a script can drive the desktop over ssh. It is a test tool in [`tools/qnx-input/rnqnx-inject.c`](https://github.com/mikevocalz/react-native-qnx/blob/main/tools/qnx-input/rnqnx-inject.c). It is not part of a shipped app.

<Callout type="warn">
  Not run in this docs pass: building the tool and every injector command. They need the QNX SDP and
  a board. The usage text and the results cited below are from the source and from receipts.
</Callout>

## Prerequisites

- The QNX SDP sourced (`source <qnx-installation>/qnxsdp-env.sh`). The build needs `QNX_TARGET`.
- A board you can reach over ssh, with password-less `sudo`. The injector runs as root because it acts as an input provider.
- An app window open on the board.

## 1. Build and copy it

```bash
tools/qnx-input/build.sh
```

It runs `qcc -Vgcc_ntoaarch64le -O2 -Wall -Wextra -Werror -o build/qnx-input/rnqnx-inject tools/qnx-input/rnqnx-inject.c -lscreen` and prints the output path. Pass a path as the first argument to change it. Copy the file to the board, for example into `/data/home/qnxuser/bin/`.

## 2. Send events

```sh
sudo rnqnx-inject click 960 540
sudo rnqnx-inject drag 900 160 1000 260 12      # title bar drag
sudo rnqnx-inject move 900 600 wheel 3           # wheel, 3 notches down
sudo rnqnx-inject dclick 960 22                  # double click
sudo rnqnx-inject mods 4 keydown alt key tab sleep 800 mods 0 keyup alt
sudo rnqnx-inject keyhold down 2500              # hold Down 2.5 s with auto-repeat
```

Coordinates are display pixels. Commands chain on one line. Without arguments the tool prints this list:

| Command | Effect |
| --- | --- |
| `move X Y` | Move the pointer. |
| `down [left\|middle\|right]`, `up` | Press at the current position, release all buttons. |
| `click X Y [button]` | Move, press, release. |
| `dclick X Y` | Two clicks 90 ms apart. |
| `drag X0 Y0 X1 Y1 [steps]` | Press at the start, move in steps, release at the end. |
| `wheel N`, `hwheel N` | N wheel ticks, vertical or horizontal. Up is negative. |
| `mods HEX` | Modifier mask for later events. |
| `key NAME\|HEX [mods]` | Press and release. Names: `esc tab ret space bksp del left right up down home end pgup pgdn alt ctrl shift`, or one character. |
| `keydown`, `keyup` | One press or one release. |
| `keyhold NAME\|HEX MS [HZ]` | Hold a key for 1 to 30000 ms like a keyboard: one press, auto-repeat after 500 ms at HZ per second (default 30, 1 to 120), then release. |
| `type TEXT` | Type ASCII text. |
| `sleep MS` | Wait. |

`keydown ... sleep ... keyup` sends one press and one release, so an app sees no auto-repeat. Use `keyhold` for that. Bad `keyhold` arguments print a message and exit 2.

## 3. Why it works

Two details made the first injector fail, and the tool handles both. Screen reads an event position only when `SCREEN_FLAG_POSITION_VALID` is set, so without it the pointer sits at 0,0 and Qt drops the click. The event must also name a pointer device made with `screen_create_device_type()`, so Screen picks the window under the pointer and converts coordinates. Screen leaves an injected timestamp at 0, so the tool sets one. Without it every pair of clicks was a double click.

## What you should see

Each command exits 0. The recorded runs wrote the exit after every call:

- Run 2 on 2026-11-19: 62 injector calls, each followed by `inject_exit=0`. `key esc` closed the Modal and the drawer. `keydown down sleep 2500 keyup down` moved focus one tab, because it sends one press.
- The key-hold run of the same day used `rnqnx-inject5` and `keyhold down 800 10` and `keyhold down 2500`. Focus moved along the five sidebar tabs. The receipt, [`pr149-pi400-keyhold-2026-11-19`](https://github.com/mikevocalz/react-native-qnx/tree/main/docs/evidence/pr149-pi400-keyhold-2026-11-19), lists the focus after each step.

These were synthetic Screen events, not a USB keyboard. A real keyboard held down is unproven.

## Smoke test the window

`pnpm pi:mouse-smoke [--build] [--no-install]` copies the injector to the Pi and checks title bar drag, right-edge resize and double-click restore against the `RNQNX_WINDOW_FRAME` lines the app logs. It needs password-less `sudo` and a restored (not maximized) window at least 700 px wide. It never starts or stops an app. Evidence goes to `artifacts/pi-mouse-smoke/<time>/`. Set `RNQNX_MOUSE_FRAME=WxH+X+Y` if the app has not logged a frame yet.

## Troubleshooting

| What you see | Cause and fix |
| --- | --- |
| Clicks land at the top left or nowhere | You are not using this tool, or the device or position flag is missing. A first injector had this fault. |
| Every click acts as a double click | The event had no timestamp. This tool sets one. |
| Nothing happens | Run it as root. The tool is an input provider. |
| The window ignores a click on the launcher tile | `demolauncher` ignores injected clicks. |
| A screenshot shows the old frame | Nudge the pointer first with `move`. See [take a device screenshot](/docs/how-to/screenshot-device). |
