Run the CLI inside a checkout as `pnpm qnx <command>`. `pnpm qnx` is the root `package.json` script `qnx`, which runs `node packages/react-native-qnx-cli/src/bin.mjs`. The CLI needs Node 26 or newer (`engines.node` is `>=26.0.0`) and pnpm 12.18.0 or newer. The package `@rn-qnx/react-native-qnx-cli` is private, so `rnqnx` is not on your PATH. Where other pages write `rnqnx`, they mean the `bin.mjs` command above.

## How this page was checked

All help blocks below are the output of commands run on 2026-11-19, with Node v26.13.0, from the repository root, in the form `node packages/react-native-qnx-cli/src/bin.mjs <args> --help`. They are pasted unchanged except for one substitution: the source also names one additional build target. This site does not document that target, so its name is replaced by `[omitted]` wherever it appears in help text.

Option types and defaults come from the `parseArgs` tables and the code that reads them in `packages/react-native-qnx-cli/src/`. Only `--help` was run. No command that builds, deploys, writes files or contacts a device was run for this page, so "what it does" statements come from source, not from an observed run. For runs that were observed, see the [verification log](/docs/reference/verification-log).

Every command parses its arguments with `node:util` `parseArgs` in strict mode. An unknown option fails. `-h` is the short form of `--help` everywhere. All `--flag value` options take a string value.

## Command map

`bin.mjs` picks a handler from the first words of the command line:

| Command line                                                               | Handler (file)                                          |
| -------------------------------------------------------------------------- | ------------------------------------------------------- |
| `doctor --target-runtime-report <file> ...`                                | `doctor.mjs`                                            |
| `project doctor`                                                           | `doctor.mjs`                                            |
| `project build-native`, `project create`, `project add-qnx`                | `build-native.mjs`, `create-project.mjs`, `add-qnx.mjs` |
| `project run`                                                              | `run.mjs`                                               |
| `project start`, `project dev`                                             | `dev-server.mjs`                                        |
| `project prepare-native`, `project desktop-entry`                          | `prepare-native.mjs`, `desktop-entry.mjs`               |
| `project inspect`, `project bundle`                                        | `project.mjs`                                           |
| `runner fetch`, `runner list`                                              | `runner.mjs`                                            |
| anything else (`init`, `bundle-qnx`, `doctor`, `configure-qnx`, and so on) | `cli.mjs`                                               |

`bin.mjs` also routes one more first word to a handler in `packages/qnx-devtools`. That command belongs to a second target and is not documented on this site.

## Exit codes

| Code | Meaning                                                                                                                                                 | Source                          |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| 0    | Success, or help printed.                                                                                                                               | all handlers                    |
| 1    | Any thrown error. `bin.mjs` prints `rnqnx: <message>` to stderr. Also the failed-check result of `project doctor` and `doctor --target-runtime-report`. | `bin.mjs`, `doctor.mjs`         |
| 2    | `project doctor` and `doctor --target-runtime-report` only: invalid invocation, or an error thrown before a result exists.                              | `bin.mjs`, `doctor.mjs`         |
| 3    | `project run` only: a step needs something the host lacks (bundle, SDP, device).                                                                        | `run.mjs` (`NEEDS_DEVICE_EXIT`) |
| 124  | `project bundle` only: Metro ran longer than 120000 ms and was stopped.                                                                                 | `project.mjs`                   |
| 130  | `project bundle` received SIGINT.                                                                                                                       | `project.mjs`                   |
| 143  | `project bundle` received SIGTERM.                                                                                                                      | `project.mjs`                   |

For the commands in `cli.mjs` that run a child process (`bundle-qnx`, `doctor`, `configure-qnx`, `build-qnx`, `deploy-qnx`, `run-qnx`, `log-qnx`, `evidence verify`), the CLI returns the child's exit code, or `128` plus the signal number if the child died on a signal. SIGINT and SIGTERM sent to the CLI are forwarded to the child. On a nonzero code, `cli.mjs` prints one `rnqnx: <command> exited with code <n>.` line with a next step for `configure-qnx`, `build-qnx`, `deploy-qnx`, `run-qnx`, `log-qnx` and `bundle-qnx`. `doctor` and `evidence` print no extra line.

All options below are declared once in `cli.mjs`, then checked against a per-command allow list. Passing an option the command does not allow fails with `<command> does not accept --<option>.`

| Option            | Type    | Default                         | Allowed on                                            |
| ----------------- | ------- | ------------------------------- | ----------------------------------------------------- |
| `-h`, `--help`    | boolean | off                             | all                                                   |
| `--dry-run`       | boolean | off                             | all except `init`                                     |
| `--app <name>`    | string  | none (required)                 | `bundle-qnx`                                          |
| `--out <path>`    | string  | `build/<app>.bundle.js`         | `bundle-qnx`                                          |
| `--arch <arch>`   | string  | `aarch64` (also `x86_64`)       | `configure-qnx`, `build-qnx`, `deploy-qnx`, `run-qnx` |
| `--config <cfg>`  | string  | `Debug` (also `Release`)        | `configure-qnx`, `build-qnx`, `deploy-qnx`            |
| `--target <name>` | string  | `rnqnx_playground`              | `deploy-qnx`, `run-qnx`                               |
| `--dir <path>`    | string  | latest `artifacts/pi` directory | `evidence verify`                                     |

`--dry-run` prints `{ executable, args, cwd }` as JSON and returns 0 without running anything. `--target` must match `^[A-Za-z0-9][A-Za-z0-9._-]*$`. The CLI finds the checkout by walking up from the current directory to a `package.json` named `react-native-qnx-monorepo` that sits beside `CMakePresets.json`. Outside a clone it fails with `Run this command inside a react-native-qnx clone.`

`rnqnx_playground` is the Screen probe. The React Native runtime target is `rnqnx_playground_qnx`.

### init

Creates `apps/<name>` from `template/qnx` (`index.js`, `metro.config.js`, `babel.config.js`, `README.md`) plus a generated `package.json`, replacing `__APP_NAME__` with the name.

| Item       | Value                                                                                                                       |
| ---------- | --------------------------------------------------------------------------------------------------------------------------- |
| Usage      | `pnpm qnx init <name>`                                                                                                      |
| Name rule  | `^[a-z][a-z0-9-]{0,62}$`, else `App name must be 1–63 lowercase letters, digits or hyphens, starting with a letter.`        |
| Options    | none                                                                                                                        |
| Errors     | `apps/<name> already exists; choose another name.`, `init needs exactly one app name, for example: pnpm qnx init dashboard` |
| Exit codes | 0, or 1 on error. Files written so far are removed if a write fails.                                                        |

```bash
pnpm qnx init dashboard
```

### bundle-qnx

Runs `metro build index.js --config apps/<app>/metro.config.js --platform qnx --dev false --max-workers 2 --out <out>` using the checkout's installed Metro, with `apps/<app>` as the working directory.

| Item       | Value                                                                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Options    | `--app` (required), `--out`, `--dry-run`                                                                                                                |
| Output     | Must resolve inside `<checkout>/build/`. `build/` itself must not be a symlink. Parent directories are created.                                         |
| Errors     | `apps/<name>/index.js not found. ...`, `Bundle output must be inside this checkout’s build/ directory.`, `Metro is not installed in this checkout. ...` |
| Exit codes | Metro's exit code, or 1 on a thrown error.                                                                                                              |

```bash
pnpm qnx bundle-qnx --app dashboard --out build/dashboard.bundle.js
```

### doctor

Runs `scripts/doctor.sh` (bash). It checks host tools, the QNX SDP environment and target settings. Per the script header, every ERROR and WARNING line is followed by a `Fix:` line, and checks that depend on a failed prerequisite are reported as SKIPPED. The script exits 0 when it counted no errors, otherwise 1. Options: `--dry-run`. Read variables are listed in [environment variables](/docs/reference/environment-variables).

`pnpm qnx doctor --target-runtime-report <file>` is a different command with the same name: see [project doctor](#project-doctor).

### configure-qnx, build-qnx

`configure-qnx` runs `scripts/configure-qnx.sh <arch> <config>`, which runs `cmake --fresh --preset qnx-<arch>-<config>` in lower case, for example `qnx-aarch64-debug`. `build-qnx` runs `scripts/build-qnx.sh`, which stops with `Configured Ninja build not found` if `build/<preset>/build.ninja` is missing and otherwise runs `cmake --build --preset <preset> --parallel`. The presets are in `CMakePresets.json`; see the [config reference](/docs/reference/config#cmake-presets).

| Option      | Default   |
| ----------- | --------- |
| `--arch`    | `aarch64` |
| `--config`  | `Debug`   |
| `--dry-run` | off       |

```bash
pnpm qnx configure-qnx --arch aarch64 --config Debug
pnpm qnx build-qnx --arch aarch64 --config Debug
```

### deploy-qnx, run-qnx, log-qnx

| Command      | Script                  | What the script does                                                                                                                                                                                   | Options                                       |
| ------------ | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------- |
| `deploy-qnx` | `scripts/deploy-qnx.sh` | Copies `build/qnx-<arch>-<config>/bin/<target>` to `$QNX_TARGET_DIR/<target>` over `scp` as a `.upload.<pid>` file, then `chmod 755` and `mv -f` into place. A failed copy removes the temporary file. | `--arch`, `--config`, `--target`, `--dry-run` |
| `run-qnx`    | `scripts/run-qnx.sh`    | Runs `cd $QNX_TARGET_DIR && exec ./<target>` on the board over `ssh`.                                                                                                                                  | `--arch`, `--target`, `--dry-run`             |
| `log-qnx`    | `scripts/log-qnx.sh`    | Runs `slog2info -w` on the board over `ssh`.                                                                                                                                                           | `--dry-run`                                   |

The scripts source `scripts/lib/qnx-target.sh`, which reads `QNX_TARGET_IP`, `QNX_TARGET_USER`, `QNX_TARGET_DIR`, `QNX_SSH_PORT`, `QNX_SSH_KEY`, `QNX_SSH_MACS`, `QNX_SSH_CONNECT_TIMEOUT`, `QNX_SSH_BATCH_MODE` and `QNX_SSH_OPTS`. Defaults and validation are in [environment variables](/docs/reference/environment-variables). Exit code is the script's: 1 for a bad argument or missing binary, otherwise what `ssh` or `scp` returned.

```bash
pnpm qnx deploy-qnx --arch aarch64 --config Debug --target rnqnx_playground
pnpm qnx run-qnx --arch aarch64 --target rnqnx_playground
```

### evidence verify

Runs `node scripts/verify-pi-evidence.mjs [<dir>]`. Per the help text it checks captured Pi evidence and writes a SHA-256 manifest. Without `--dir` it uses the latest directory under `artifacts/pi`. `evidence` without the word `verify` fails with `Use pnpm qnx evidence verify [--dir <path>].` `--dir` must be non-empty. The script sets exit code 1 on failure.

```bash
pnpm qnx evidence verify --dir artifacts/pi/2026-11-13
```

The directory in this example is illustrative; no such directory was checked.

## project commands

`project` commands work on an app outside the checkout (or inside it). Most take `--project <directory>`, which defaults to the current directory `.`. Most take `--platform`, which defaults to `qnx`; `qnx` is the only value this site documents. The same option given twice fails with `Duplicate option --<name>.` for the commands that check tokens (`project inspect`, `project bundle`, `project create`, `project prepare-native`, `project build-native`, `project doctor`).

### project inspect, project bundle

Command run: `node packages/react-native-qnx-cli/src/bin.mjs project --help` (2026-11-19).

```text
React Native QNX external-project bundling

  project inspect --project <directory> [--platform qnx|[omitted]] [--entry index.js]
  project bundle  --project <directory> [--platform qnx|[omitted]] [--entry index.js]
                  [--out build/<platform>/app.bundle.js] [--dry-run]

QNX is the default. The project supplies installed Metro and its target config:
metro.qnx.config.js (else metro.config.js) for qnx; metro.[omitted].config.js for [omitted].
Output must be a NEW file below the project's build/ directory.
This produces JavaScript only, not a native project, module registration or deployment.
```

| Option            | Type    | Default                          | Meaning                                                                                      |
| ----------------- | ------- | -------------------------------- | -------------------------------------------------------------------------------------------- |
| `--project <dir>` | string  | `.`                              | Project root. Must hold a `package.json` of at most 1 MiB with a nonempty `name`.            |
| `--platform`      | string  | `qnx`                            | Target platform.                                                                             |
| `--entry <file>`  | string  | `index.js`                       | Entry file, project-relative with no `.`, `..`, empty segment, backslash or symlink.         |
| `--out <file>`    | string  | `build/<platform>/app.bundle.js` | Output. Must be a `.js` file below the project's `build/` and must not exist yet (`bundle`). |
| `--dry-run`       | boolean | off                              | `bundle` only: print the plan as JSON, write nothing.                                        |

`inspect` accepts neither `--out` nor `--dry-run`. It prints the plan (project, entry, Metro config, output path, Metro CLI path and version) as JSON and writes nothing. The Metro config is `metro.qnx.config.js` if present, else `metro.config.js`. Metro is resolved from the project's own `node_modules`. `bundle` runs `metro build <entry> --config <config> --platform <platform> --dev false --max-workers 2 --out <staging file>` in a new process group, with a 120000 ms limit, and links the result into place only if it is a nonempty regular file. It supports Linux and macOS hosts only. Exit codes: 0, Metro's own code, 124, 130, 143, or 1 on a thrown error.

```bash
pnpm qnx project bundle --project ../notes
```

| Option                 | Type    | Default | Meaning                                                                                     |

The command also accepts one more boolean option for a second target. It is not documented here. It runs `npm pack --ignore-scripts` for `@rn-qnx/react-native-qnx`, `@rn-qnx/metro-config-qnx` and `@rn-qnx/expo-router-qnx` into `vendor/`, then writes `package.json`, `app.json`, `assets/icon.png`, `pnpm-workspace.yaml`, `patches/`, the router starter from `template/qnx-router`, `babel.config.js`, `metro.config.js`, `.gitignore`, `platform-packages.json` and `build/qnx/`. It supports Linux and macOS only, needs `npm` on PATH, and removes the new directory if a step fails. It installs nothing. Exit codes: 0, or 1 on error (`Specify --project with a new directory.`, `Destination exists; existing applications cannot be overwritten.`).

```bash
pnpm qnx project create --project ../notes --app-id org.example.notes --name Notes
```

### project prepare-native

Command run: `node packages/react-native-qnx-cli/src/bin.mjs project prepare-native --help` (2026-11-19).

```text
React Native QNX native consumer configuration
  project prepare-native --project <directory> [--platform qnx|[omitted]]
                         [--bundle build/<platform>/app.bundle.js]
                         [--identity-tool <path>]
                         [--dry-run]

Resolves app.json or app.config.js/ts through @expo/config (config plugins
included) and reads expo.name, expo.icon and
expo.extra.rnqnx.{appId,componentName,window,icon,shortName}.
Direct dependencies whose package.json declares "react-native-qnx": {"nitro":
{...}} for the platform are recorded as nitroModules (docs/adr/0019), and those
declaring {"expo": {...}} as expoModules together with the resolved expo config
(read by the expo-constants port). Only JSON is read for that; no package code
runs.
Set the extra.rnqnx values through the @rn-qnx/expo-qnx-config-plugins entry
in "plugins".
The icon must be a square PNG of at least 1024x1024. With no icon set, the
default template/qnx/assets/icon.png is used and a notice names expo.icon.
The tile label (shortName, else expo.name) must fit the target launcher on
one line.
Every run generates the icon set with rnqnx_identity_tool, a Qt host program
from native/app-identity: --identity-tool, else RNQNX_IDENTITY_TOOL, else the
tool under build/identity-tool in this checkout, which is built with CMake
and Qt 6.11.1+ the first time it is missing. On a host where it cannot be
built (anything but Linux and macOS) prepare-native fails; there is no
option to continue without an icon set.
Writes build/<platform>/icons/ and build/<platform>/native-app.json for the
existing native CMake backend.
An identical rerun keeps the existing files. Changed generated output is not
overwritten: remove only native-app.json after reviewing your app/bundle
change, then rerun.
This does not install packages, compile native code or deploy to a device.
```

| Option                   | Type    | Default                          | Meaning                                                                                                      |
| ------------------------ | ------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `--project <dir>`        | string  | `.`                              | Project root.                                                                                                |
| `--platform`             | string  | `qnx`                            | Target platform.                                                                                             |
| `--bundle <file>`        | string  | `build/<platform>/app.bundle.js` | Must start with `build/<platform>/`, be a regular file, and be at most 256 MiB.                              |
| `--identity-tool <path>` | string  | see below                        | Qt host tool that makes the icon set.                                                                        |
| `--dry-run`              | boolean | off                              | Generate in a temporary directory and print the result, write nothing in the project.                        |
| `--skip-identity-tool`   | boolean | none                             | Parsed, then rejected: `--skip-identity-tool was removed: every prepared app gets a generated icon set. ...` |

Identity tool lookup order: `--identity-tool`, then `RNQNX_IDENTITY_TOOL`, then `build/identity-tool` in the checkout (built with CMake option `RNQNX_BUILD_IDENTITY_TOOL=ON` the first time it is missing; `RNQNX_IDENTITY_TOOL_BUILD_DIR` moves that directory). Output: `build/<platform>/native-app.json` (at most 64 KiB) and `build/<platform>/icons/icon-<size>.png` for sizes 16, 24, 32, 48, 64, 96, 128, 192, 256 and 512. The printed JSON has `action` set to `created`, `unchanged` or `dry-run`. A rerun whose output differs from the existing `native-app.json` fails with `Generated native configuration differs; review and remove only native-app.json before preparing again.` Exit code 0, or 1 on error. The fields of `native-app.json` and the app config it reads are in the [config reference](/docs/reference/config).

```bash
pnpm qnx project prepare-native --project ../notes --bundle build/qnx/app.bundle.hbc
```

### project build-native

Command run: `node packages/react-native-qnx-cli/src/bin.mjs project build-native --help` (2026-11-19).

```text
React Native QNX - build an external native consumer application
  project build-native --project <directory> [--platform qnx|[omitted]]
                       [--host-preview] [--window-chrome] [--dry-run]

QNX defaults to the QNX toolchain; --host-preview is an explicit Linux-only
QNX app preview. [omitted] builds a separate Linux executable using Qt/Wayland.
--window-chrome compiles the experimental title bar from native-app.json
"window" (RNQNX_ENABLE_WINDOW_CHROME, default OFF; see docs/adr/0016).
Nitro modules recorded in native-app.json "nitroModules" are added with
add_subdirectory, linked and registered at startup (docs/adr/0019). They
need the QNX toolchain build; --host-preview rejects them.
Requires the reviewed source checkout/native prerequisites. No deployment.
```

| Option            | Type    | Default | Meaning                                                                                                                              |
| ----------------- | ------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `--project <dir>` | string  | `.`     | Project root with a prepared `build/<platform>/native-app.json`.                                                                     |
| `--platform`      | string  | `qnx`   | Target platform.                                                                                                                     |
| `--host-preview`  | boolean | off     | Linux hosts only. Uses CMake preset `linux-host-renderer` instead of `qnx-aarch64-debug`. Rejected if Nitro modules are recorded.    |
| `--window-chrome` | boolean | off     | Passes `-DRNQNX_ENABLE_WINDOW_CHROME=ON`. Without it the CLI passes `OFF` explicitly. Fails if the window `titleBarStyle` is `none`. |
| `--dry-run`       | boolean | off     | Print the plan with `configure` and `build` argument lists, run nothing.                                                             |

A real QNX build also needs `QNX_HOST` and `QNX_TARGET` in the environment (`QNX_HOST and QNX_TARGET must select an installed licensed QNX SDK.`) and a `.hbc` bundle (`Real QNX builds require a prepared matching Hermes .hbc bundle.`).
