---
title: Error codes and messages
description: User-visible error strings and codes thrown by the CLI, scripts, JavaScript packages and native runtime, with file and line, meaning and fix.
---

This page lists errors and failure messages found by reading the source, grouped by area. Strings are quoted from the source. A `${name}` or `$VAR` inside a string is filled in at run time. Where a message is long, the table quotes its first sentences; the file and line locate the rest.

Scope and limits:

- This is a selection of the roughly 250 throw and print sites in the CLI plus the native and JavaScript packages, not an exhaustive index. Option-parsing duplicates ("Duplicate option --x") and ELF or tar parser internals are left out.
- The only stable numeric codes in the source are the exit codes listed under "Exit codes". Everything else is a message string, and a message can change without notice.
- Line numbers come from the repository state this page was written against, and drift as files change. Search for the quoted text if a line no longer matches.
- "Fix" is taken from the message itself or from the surrounding code. Where the source gives no guidance the column says so.

### Project doctor check ids (`rnqnx doctor`)

Each check has an `id` and a `status` of `passed`, `failed` or `not-checked` (`packages/react-native-qnx-cli/src/doctor.mjs`). The ids found in source: `app-identity`, `app-icon`, `tile-label`, `identity-tool`, `node`, `project-manifest`, `package-manager`, `nitro-modules`, `package-graph`. Failure messages for the `node` check read `Use the documented Node version before building.` (`doctor.mjs`, `node` check). `package-manager` fails when `packageManager` differs from the platform contract.
