## Install

The root `package.json` pins `react-native-reanimated` at `4.7.1` and `react-native-worklets` at `0.13.1`. Reanimated 4.7.1 requires Worklets 0.13.x. `docs/reanimated-gesture-handler-qnx.md` gives its React Native range as 0.86 to 0.88. The app installs the npm package as usual. The upstream C++ is compiled from `node_modules` and is not vendored (ADR-0020, referenced from `docs/reanimated-gesture-handler-qnx.md`).

The platform glue is `vnext/src/reanimated/QnxReanimatedModule.cpp` and `QtReanimatedPlatform.cpp`. `QnxReanimatedModule` is the `ReanimatedModule` TurboModule. Its `installTurboModule()` builds the upstream `ReanimatedModuleProxy`.

## Setup

Reanimated is off unless you switch it on. In `cmake/RnqnxReanimated.cmake` the option is `RNQNX_ENABLE_REANIMATED` (default OFF). It stops the configure step unless `RNQNX_ENABLE_WORKLETS` is also ON.

```sh
cmake ... -DRNQNX_ENABLE_WORKLETS=ON  -DRNQNX_WORKLETS_SOURCE_DIR=<node_modules>/react-native-worklets \
          -DRNQNX_ENABLE_REANIMATED=ON -DRNQNX_REANIMATED_SOURCE_DIR=<node_modules>/react-native-reanimated
```

The configure step reads the package version and fails outside the supported range. It text-patches two upstream lines in generated copies and fails if either changes: the `SynchronouslyUpdateUIPropsFunction` type in `PlatformDepMethodsHolder.h`, and the Apple-only loop in `ReanimatedModuleProxy.cpp` that applies synchronous props (it becomes `__APPLE__ || defined(__QNX__)`). It also prefixes two enum headers with `#include <cstdint>`. Fabric codegen for the library's component specs is generated into the build directory.

No Metro or Babel change is needed for Reanimated itself. See [Worklets](/docs/reference/modules/worklets) for the Babel plugin. The build steps are in [Expo setup](/docs/how-to/expo-setup).

## Supported API

From `docs/reanimated-gesture-handler-qnx.md`, the platform methods the module provides:

| Platform method                                            | Qt implementation                                                            |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `requestRender`                                            | Qt Quick `afterAnimating`, through the Worklets frame bridge                 |
| `getAnimationTimestamp`                                    | `steady_clock` milliseconds                                                  |
| `synchronouslyUpdateUIPropsFunction`                       | GUI-thread update of the mounted item                                        |
| Fabric commit and mount hooks, measure, `dispatchCommand`  | Upstream code over the host `UIManager`; mounting re-posts to the GUI thread |
| Events for `useAnimatedScrollHandler` and gesture handlers | `Scheduler::addEventListener`; the handler worklet runs on the UI thread     |

Observed to work: `withTiming` and `withSpring` moving a mounted view, and a bounded SVG layout-event path when SVG and Reanimated are both enabled. No evidence found for other hooks or animation functions individually.

## Not supported

- Sensors and keyboard: not provided. They log and return -1.
- Pseudo-selectors and platform CSS backends: not provided.
- `useAnimatedStyle` conformance, layout animations and scroll behavior: not qualified. The doc lists "layout/scroll behavior" as unqualified.
- Animated SVG props through `useAnimatedProps`: no device receipt.
- Smooth animation while JavaScript is busy. JS runs on the Qt GUI thread, so a busy JS thread stops repainting. A dedicated JS thread is described in the platform plan and is not built.
