## Install

The root `package.json` pins `react-native-gesture-handler` at `3.4.0`. `docs/reanimated-gesture-handler-qnx.md` explains the choice. Expo SDK 58's `bundledNativeModules.json` selects `~3.3.0`, but the upstream table lists 3.4.x for React Native 0.88, so the app must pin 3.4.0 itself. `expo install` would pick the older line.

The library's JavaScript and its detector shadow node are upstream's. The recognizers are ours, in `vnext/src/gesture/GestureHandlerCore.cpp`, a registry with no Qt or React dependency. Input comes from `QtGestureInput.cpp`, and the module is `QnxGestureHandlerModule`.

## Setup

`cmake/RnqnxGestureHandler.cmake` defines `RNQNX_ENABLE_GESTURE_HANDLER` (default OFF). It needs `RNQNX_ENABLE_WORKLETS` and builds with `RNGH_USE_WORKLETS=1`.

```sh
cmake ... -DRNQNX_ENABLE_WORKLETS=ON -DRNQNX_ENABLE_GESTURE_HANDLER=ON \
          -DRNQNX_GESTURE_HANDLER_SOURCE_DIR=<node_modules>/react-native-gesture-handler
```

The configure step checks the package version. See [Worklets](/docs/reference/modules/worklets) for the Hermes and Babel requirements.

## Supported API

From `docs/reanimated-gesture-handler-qnx.md`:

| Handler   | Implemented behavior                                                                               |
| --------- | -------------------------------------------------------------------------------------------------- |
| Pan       | Min distance, active and fail offsets, velocity, translation, begin, activate, update, end, cancel |
| Tap       | Tap count, max duration, max delay between taps, max distance                                      |
| LongPress | Min duration deadline, max distance                                                                |
| Fling     | Direction mask, minimum velocity                                                                   |
| Manual    | Driven by `GestureStateManager` through `_setGestureStateSync` and `_setGestureStateAsync`         |

Arbitration: by default the first handler to activate fails every other begun or active handler that shares a pointer. `simultaneousHandlers` allows two active together. `waitFor` and `blocksHandlers` hold a handler at Began until the other fails or ends.

Input is Qt mouse and touch events, seen through an event filter that does not consume them, so React responders and `Pressable` still work. Detaching, disabling or moving a handler cancels its current contact. Removing a detector cancels its handlers as one batch.

## Not supported

- Pinch, Rotation, Native and Hover: accepted, then fail on the first pointer with a log line.
- Pointer data callbacks (`onTouchesDown` and similar), multi-pointer pan averaging, hit-slop.
- `RNGestureHandlerButton` behavior: it mounts as a plain container.
- Arbitration with Qt scrolling.
- Coordinate spaces for transformed ancestors: the view's `mapFromScene` is used.
- A stack navigator through expo-router. See [expo-router](/docs/reference/modules/expo-router).
- Gestures while JavaScript is blocked. The GUI thread owns rendering.

The doc states they do not cover pinch, rotation, multi-pointer input, 1920x1080, or a gesture while JavaScript is blocked. `docs/component-support.json` still records physical HID input as unverified for `Pressable`.
