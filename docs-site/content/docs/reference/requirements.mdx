The JavaScript-only path in the [quick start](/docs/tutorials/quick-start) needs Node, pnpm and Git. It does not need CMake, Ninja, Python or Qt. Those matter when you build the host playground or the native binaries.

The quick start records its runs on macOS arm64 with Node 26.13.0 and pnpm 12.21.0.

### CMake presets

[CMakePresets.json](https://github.com/mikevocalz/react-native-qnx/blob/main/CMakePresets.json) uses preset schema version 6 and the Ninja generator. The presets include `macos-host-debug`, `macos-host-release`, `macos-host-tests`, `linux-host-debug`, `linux-host-tests`, `qnx-aarch64-debug` and `qnx-pi4`. The macOS presets only appear on Darwin and the Linux presets only on Linux. The two QNX presets use the toolchain file `vnext/cmake/qnx-aarch64le.toolchain.cmake`.

`qnx-pi4` sets `RNQNX_G0_PROBE_ONLY=ON`, so it configures only the C++20 probe. The preset description says a configure or build is not a passed gate until the binary runs on the Pi.

### Optional CMake switches

These are default `OFF` in [CMakeLists.txt](https://github.com/mikevocalz/react-native-qnx/blob/main/CMakeLists.txt). Turn on the ones you need.

| Switch                       | What it builds                                                       |
| ---------------------------- | -------------------------------------------------------------------- |
| `RNQNX_BUILD_HERMES`         | Hermes from source for the host. Slow, so opt-in.                    |
| `RNQNX_BUILD_HERMES_QNX`     | The cross-built QNX Hermes and JSI probe.                            |
| `RNQNX_BUILD_REACT_QNX`      | The full React Native, Hermes, Fabric and Qt Quick QNX target graph. |
| `RNQNX_BUILD_PLAYGROUND_QNX` | The visual Qt Quick and Fabric playground for QNX.                   |

## Target and QNX

From the "Target and toolchain" table in [the compatibility matrix](https://github.com/mikevocalz/react-native-qnx/blob/main/docs/getting-started/compatibility-matrix.md) and [docs/toolchain.md](https://github.com/mikevocalz/react-native-qnx/blob/main/docs/toolchain.md).

| Requirement          | Version                                                     | Source                                                                                                                                               |
| -------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| QNX cross-build host | Licensed QNX SDP 8.0.5 on a supported x86-64 host           | Compatibility matrix                                                                                                                                 |
| Compiler target      | `gcc_ntoaarch64le` (GCC 12.2.0 in the SDP 8.0.5 check)      | [docs/toolchain.md](https://github.com/mikevocalz/react-native-qnx/blob/main/docs/toolchain.md), 2026-11-06 entry                                    |
| Experimental Pi 400  | Custom BCM2711 image, Qt 6.12.0 evaluation build, QNX 8.0.5 | Compatibility matrix; [Hello World receipt](https://github.com/mikevocalz/react-native-qnx/blob/main/docs/evidence/pi400-hello-world-2026-11-07.txt) |
| Stock Pi 4 and Pi 5  | QSTI 0.5.0 build 50                                         | Compatibility matrix. Full runtime and device parity still need receipts.                                                                            |

Compiling with the SDP is separate from running on a device. The compatibility matrix says so in its evidence column, and the Pi 400 row is "not stock QSTI validation".

Qt for the Pi 400 runtime uses a restricted module subset and a licensed evaluation. [docs/toolchain.md](https://github.com/mikevocalz/react-native-qnx/blob/main/docs/toolchain.md) says that evaluation evidence does not resolve production distribution. Read [ADR-0011](https://github.com/mikevocalz/react-native-qnx/blob/main/docs/adr/0011-qt-module-licensing.md) before you ship.
