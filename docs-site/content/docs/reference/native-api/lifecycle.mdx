```cpp
class HostWindowState final : public QObject
```

Doc comment:

```text
One per process. The object lives on the QGuiApplication owner thread no
matter which thread calls instance() first: with the JavaScript thread on
its own thread, QnxAppStateModule can be the first caller, and a QObject that
stayed on that thread would queue the applicationStateChanged mirror update
onto a thread with no event loop. attach() must run on the owner thread and
throws std::logic_error elsewhere. setMinimized() may be called from any
thread: the flag changes at once and minimizedChanged() is emitted on the
owner thread, in the order the flag changed (a change made on the owner
thread waits behind any foreign-thread change still queued). minimized() and qtApplicationState() may be read from any
thread: AppState's first value is read on the JavaScript thread before its
GUI-side observer exists.

instance() needs the QGuiApplication to exist. Before that the object would
have no owner thread to live on, so it throws std::logic_error.
```

### `rnqnx::runtime::QtApplicationLifecycle`

Kind: class · Namespace: `rnqnx::runtime` · Source: [native/lifecycle/QtApplicationLifecycle.h#L32](https://github.com/mikevocalz/react-native-qnx/blob/main/native/lifecycle/QtApplicationLifecycle.h#L32)

```cpp
class QtApplicationLifecycle final : public QObject
```

Doc comment:

```text
The visibility has two sources. Qt's applicationStateChanged, and the host
(HostWindowState), which says the window was minimized or restored. The host
wins while the window is minimized: Hidden (JS: "background"). On restore the
observer reports Active at once, then follows Qt again. This is how AppState
changes on QNX Screen, where Qt may report nothing when the native window is
destroyed (ADR-0024).

Observation only: does not suspend a process, grant background execution,
persist state, or promise that the platform reports every lifecycle change.
Construct, read, close and destroy on the QGuiApplication owner thread.
Connect first, then read snapshot() on that thread for initial state.
```

```cpp
struct LifecycleObserverDeleter
```

Doc comment:

```text
Ends an observer from the thread that releases it. On the owner thread it
closes and deletes at once. From any other thread (a module torn down on the
JavaScript thread after the event loop that would run a posted task is gone)
it hands the object to deleteLater(), which is thread safe: the owner thread
deletes it, or the object is reclaimed with that thread's event data. A QObject
is never deleted off its own thread, and no Qt call needs the owner thread.
```
