## Behavior and limits

Styled, wrapped text and numberOfLines ellipsis. Inline attachments have zero size. The same gallery capture shows styled Text in many cards. Wrapping and numberOfLines are not shown on the device.

## Props

`Text` is React Native's Fabric `Paragraph` descriptor (plus the nested `Text` and `RawText` descriptors), registered in `vnext/src/runtime/QtReactHost.cpp`. The adapter maps `Paragraph` to a Qt Quick `Text` item. Measuring uses a QNX `TextLayoutManager` (`vnext/src/text/QtTextLayoutManager.cpp`) built on `QTextLayout`, because React Native's generic C++ manager returns the minimum size and would collapse every Text.

## Events

`onTextLayout` is never dispatched. `ParagraphShadowNode::layout` in React Native 0.88.1 calls `measureLines` only when `TextLayoutManagerExtended::supportsLineMeasurement()` is true, which is a compile-time check that the manager type has a `measureLines` member (`ReactCommon/react/renderer/components/text/ParagraphShadowNode.cpp:351-361`, `ReactCommon/react/renderer/textlayoutmanager/TextLayoutManagerExtended.h:58-63`). The QNX manager defines only `measure` (`vnext/src/text/QtTextLayoutManager.cpp:63-152`), so the branch that would emit the event compiles to a warning, "onTextLayout is not supported by the current platform". A search of `vnext/` and `native/` finds no `measureLines`.

`onPress` and the other press callbacks are JavaScript. `Text` wraps them in Pressability (`react-native/Libraries/Text/Text.js:150-300`) and passes responder and touch handlers to the native text component. The paragraph's event emitter derives from `ViewEventEmitter`, whose base is `TouchEventEmitter` (`ParagraphEventEmitter.h:17`, `BaseViewEventEmitter.h:22`), and `registerEventEmitter` registers any `TouchEventEmitter` with the dispatcher (`ShadowViewMutationAdapter.cpp:1035-1062`). The hit test returns the deepest item under the point, which for a Text is the Qt Quick `Text` item. So the path from a touch on a Text to the responder events exists by code reading. No host test presses a Text: the Pressable probe (`tests/cpp/QtPressableProbe.cpp`) drives a `Pressable`. Nested `Text` spans have no item of their own (only `Paragraph` is mapped to a QML type), so a touch on a nested span targets the whole paragraph. Per-span `onPress` was not traced further.

## Platform behavior on QNX

Text is measured against the available width with `QTextLayout`, and the Qt item is set to `Text.Wrap` so the painted lines match the measured height (comment in `QtQuickMountingLayer::updateText`). When more than one styled fragment exists, the paragraph is sent as Qt rich text, because a Qt Quick `Text` applies one font and color to the whole item. Plain strings use `PlainText`, so markup characters are never interpreted. Mounting runs on the Qt GUI thread; see [threading](/docs/explanation/threading).

## Unsupported or partial props

The adapter hands the mounting layer a `TextStyle` (`vnext/include/react-native-qnx/fabric/QtQuickMountingLayer.h:96-114`). Its fields are text, rich text, size, color, mixed-style flag, line limit, elide mode and family. A text prop that is not one of those, or one of the CSS properties in `fragmentStyleAttribute` (`ShadowViewMutationAdapter.cpp:104-126`: `font-size`, `color`, `font-weight`, `font-style`, `font-family`), is dropped in `paragraphTextStyle` (lines 128-199).

- `textAlign`: ignored. React Native carries it as `TextAttributes::alignment`; `paragraphTextStyle` never reads it, the rich-text spans carry no `text-align`, and the playground Text QML is `Text { visible: true }` (`vnext/probes/playground/main.cpp:164`). Text is left aligned in the item. The measured width does not depend on it.
- `lineHeight`: ignored. `QtTextLayoutManager::measure` sums `QTextLine::height()` from Qt's natural line metrics (lines 127-138), and nothing sets a line height on the item. A style with a larger `lineHeight` gets a Yoga box sized to natural lines.
- `letterSpacing`: ignored in both measure and paint. The `letterSpacing` hits under `native/qt/rnsvg` belong to SVG text.
- `textDecorationLine`: ignored. No `underline` or `strikeout` is set in measure, in the CSS, or on the item.
- `selectable`: ignored. In `Text.js` the prop selects `NativeSelectableText` only when `enablePreparedTextLayout()` is true, and otherwise renders the ordinary `NativeText`. The flag's default is false (`ReactNativeFeatureFlags.js:386`, `ReactNativeFeatureFlagsDefaults.h:200`), and the QNX flag set (`QtReactHost.cpp:454-465`) overrides only two other flags. `BaseParagraphProps::isSelectable` is not read by the adapter. If the flag were on, the host would also need a `SelectableParagraph` descriptor, which `registeredBuiltinComponentNames` (`QtReactHost.cpp:313-341`) does not list.
- `allowFontScaling`: ignored. `Text.js` sets it on the native props; no QNX source reads `allowFontScaling` (only a router test mentions the name).
- `onTextLayout`: never called, as described under Events.
- Inline attachments (views inside Text): `QtTextLayoutManager.cpp` reports them as zero-sized. The comment states this platform has no attachment support.
- `elide` without `numberOfLines`: `updateText` only sets elide inside the one-line and multi-line branches (`QtQuickMountingLayer.cpp:714-721`).
- `fontWeight` and `fontStyle` on a single-style Text: `fontForFragment` applies them when measuring (`QtTextLayoutManager.cpp:43-52`), but the plain path in `updateText` (lines 732-745) sets only pixel size and family, so the item paints in the QML default weight and slant. In the mixed path they are written into the spans. No test sets `fontWeight` on a Text, so the mismatch is from code reading.

### The comment above `fragmentStyleAttribute`

The block comment at `ShadowViewMutationAdapter.cpp:98-103` says per-fragment font, colour and weight "are measured by the text layout manager but not yet carried onto the Qt item, so a paragraph renders with one style". That is stale. The comment is also detached from the function it described (`paragraphTextStyle`), and it now sits above `fragmentStyleAttribute`. What the code does today:

- `paragraphTextStyle` builds a `<span style="...">` per fragment with `fragmentStyleAttribute` (lines 148-152) and sets `mixedStyles` when more than one fragment exists (line 173).
- `updateText` switches to `Text.RichText` and sets the markup when `mixedStyles` is true (`QtQuickMountingLayer.cpp:727-730`).
- The host test checks `textFormat == 1` and that the markup contains `font-size:20px` and `#ffcc00` (`tests/cpp/QtReactHostHostTest.cpp:1385-1395`).
- `docs/component-support.md` lists "Mixed styling in one block" as supported.

The test covers size and color. The `font-weight`, `font-style` and `font-family` declarations are emitted by code but no test asserts them. A comment on `TextStyle` (`QtQuickMountingLayer.h:96-98`) says only the first fragment's values are used, which is true only for the non-mixed path. Both comments are source files outside this docs change, so they are reported here and not edited.

## Minimal example

```tsx
import React from 'react';
import { Text, View } from 'react-native';

export default function App() {
  return (
    <View style={{ padding: 16, width: 240 }}>
      <Text style={{ fontSize: 18, color: '#222222' }} numberOfLines={2} ellipsizeMode="tail">
        A long line of text that wraps and is cut at two lines with an ellipsis.
        <Text style={{ color: '#cc3300' }}> Nested spans use rich text.</Text>
      </Text>
    </View>
  );
}
```

## Known gaps

- Inline attachments have zero size.
- `textAlign`, `lineHeight`, `letterSpacing`, `textDecorationLine`, `selectable`, `allowFontScaling` and `onTextLayout` have no effect. They are verified as dropped in the adapter and the layout manager, not just unfound.
