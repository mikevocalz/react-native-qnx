## Behavior and limits

Host pointer press delivers onPress. Pi 400 synthetic Qt input exercises real React Pressable/responder dispatch and remount recovery; physical HID, RNGH and Worklets remain unverified.

## Props

`Pressable` has no QNX override: `packages/react-native-qnx/Libraries/Components` contains only Button, KeyboardAvoidingView, RefreshControl, ScrollView, StatusBar, Switch and TextInput. The component is React Native's own (RN 0.88.1 per the evidence receipt). It builds a `Pressability` config (`Pressable.js:283-345` upstream) and attaches responder handlers to a `View`. React decides press, long press and cancel in JavaScript from the four Fabric touch events, using `setTimeout` for delays (`Pressability.js:464-478`). Host tests install the timers module (`installTimers()` in every fixture in `tests/cpp/QtReactHostHostTest.cpp`).

What the native touch path delivers: Fabric `onTouchStart`, `onTouchMove`, `onTouchEnd` and `onTouchCancel`, nothing else. `QtTouchDispatcher::emitTouchEvent` (`vnext/src/fabric/QtTouchDispatcher.cpp:227-247`) and the mouse branch (lines 280-360) call only those four emitter methods. It handles `QMouseEvent` press, move and release, `QTouchEvent` begin, update and end, and, with the input lifecycle on, `TouchCancel`, `WindowDeactivate` and `UngrabMouse` as cancel (lines 251-278). No hover, pointer enter or pointer leave event is emitted: the host test `mouseCaptureCancellationDoesNotCreateHoverTouches` sends a button-less `MouseMove` and expects `dispatchedCount() == 0` (`tests/cpp/QtReactHostHostTest.cpp:1117-1127`, lifecycle on). Hit testing uses item geometry only (`deepestItemAt`, `hitTest`, lines 141-225). The one other path is a `click` event for accessible views that subscribe to it (`ShadowViewMutationAdapter.cpp:1038-1050`).

## Platform behavior on QNX

The input lifecycle is behind a default-OFF CMake option. The remount fix needs a three-file RN patch that forwards null-target `topTouchCancel` when `__RNQNX_INPUT_LIFECYCLE__` is strictly true. Without it, a press pending during `stopSurface` leaves responder state alive and the next `onPressIn` never runs (receipt `docs/evidence/pressable-qnx-2026-11-07.md`). A claimed responder keeps the gesture for its remainder (`QtTouchDispatcher.cpp:299-302`).

## Unsupported or partial props

- `android_ripple`: no effect, see above.
- `onHoverIn`, `onHoverOut`: never fire.
- `hitSlop` cannot enlarge the area in which a press starts.
- `pointerEvents` on ordinary views: the dispatcher reads `pointerEvents` only for SVG elements (`QtTouchDispatcher.cpp:154-160`) and `ExpoImageItem`. No evidence found that a `View` with `pointerEvents` none is skipped.
- Gesture handler integration: the receipt states it does not implement RNGH or Worklets.

## Minimal example

```tsx
import { useState } from 'react';
import { Pressable, Text } from 'react-native';

export default function Counter() {
  const [n, setN] = useState(0);
  return (
    <Pressable onPress={() => setN(n + 1)} style={{ padding: 12, backgroundColor: '#ddd' }}>
      <Text>Pressed {n} times</Text>
    </Pressable>
  );
}
```

## Known gaps

- Pi 400 evidence uses synthetic Qt input. Physical HID delivery is unverified.
- RNGH and Worklets are unverified (`docs/reanimated-gesture-handler-qnx.md` covers their separate audit).
- The input lifecycle is default OFF; with it off, no evidence covers cancel and remount recovery.
- Long press, retention offset and `hitSlop` regions have no test on QNX.
- Pi 4 QSTI is untested.
