## Behavior and limits

Controlled/default text, focus/blur, edit/selection/key/submit events and basic styling. Pi400 proof uses synthetic Qt input through actual React with the default-OFF TextInput contract enabled: edit counts, UTF-16 selection and Tab/Backtab focus traversal. Physical HID, software keyboard, IME provider and assistive technology remain unqualified.

## Props

`TextInput` is overridden in `packages/react-native-qnx/Libraries/Components/TextInput/TextInput.js`. The wrapper renders React Native's single-line iOS native component (`RCTSingelineTextInputNativeComponent`) and forwards every prop to it with `Object.assign` (`TextInput.js:82-98`). The wrapper does not translate `inputMode` or `enterKeyHint`: React Native's own `TextInput.js` maps them to `keyboardType` and `returnKeyType` (upstream lines 696-717 and 936-942), and this override skips that code. Native code reads a fixed set of props in `applyTextInput` (`vnext/src/fabric/ShadowViewMutationAdapter.cpp:516-570`), passes them to `QtQuickMountingLayer::updateTextInput` (`QtQuickMountingLayer.cpp:503-596`), which sets properties on the QML item from `vnext/src/views/qt/QtTextInputQml.cpp`.

"Traced" below means: JS wrapper, then C++ props, then `applyTextInput`, then the mounting layer, then QML, then tests, all read. "Not read" means the C++ props struct parses the value but nothing in `vnext/` reads it.

## Platform behavior on QNX

React Native's own `TextInput.js` branches on `Platform.OS` and has no `qnx` branch, so without this override nothing renders. The override uses the portable iOS single-line descriptor, which the QNX mount layer already handles. Editors are QML items from `vnext/src/views/qt/QtTextInputQml.cpp`: a `TextInput` for single line and a `TextEdit` for multiline. The file holds two copies of the QML, selected by `RNQNX_ENABLE_TEXT_INPUT_CONTRACT`.

With the default-OFF TextInput contract enabled, the Qt bridge (`QtTextInputBridge.cpp`) owns an edit token, rejects stale text and selection commands, and suppresses feedback from JS writes. Each editable wrapper then gets one Qt tab stop; Tab and Backtab both map to the RN Tab key value (`tests/native/text-input/BridgeTest.cpp:60-67`).

## Unsupported or partial props

- Secure multiline: with the contract on, `TextInput.js` throws `RNQNX_TEXT_INPUT_SECURE_MULTILINE_UNSUPPORTED`, and the bridge hides the field and answers input-method queries with empty text (`QtTextInputBridge.cpp:95-104,222-240`). With the contract off, no guard was found.
- Software-keyboard props (`keyboardType`, `returnKeyType`, `inputMode`, `enterKeyHint`, `autoCapitalize`, `autoCorrect`): parsed by React Native's C++ props, not read by any QNX code. They have no effect.
- `autoFocus` and `selectTextOnFocus`: not read.
- `onEndEditing`, `onContentSizeChange`, `onScroll`: never emitted.
- `maxLength` on multiline fields: not enforced.
- `onSubmitEditing` on multiline fields: not raised.

## Minimal example

```tsx
import { useState } from 'react';
import { TextInput, View } from 'react-native';

export default function Field() {
  const [text, setText] = useState('');
  return (
    <View style={{ padding: 16 }}>
      <TextInput
        value={text}
        onChangeText={setText}
        placeholder="Name"
        maxLength={32}
        style={{ fontSize: 18, height: 40 }}
      />
    </View>
  );
}
```
