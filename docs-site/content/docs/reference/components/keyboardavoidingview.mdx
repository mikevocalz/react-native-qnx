## Behavior and limits

Renders children as a View; behavior, keyboardVerticalOffset and enabled are ignored because no Keyboard module is wired.

## Props

`KeyboardAvoidingView` is overridden in `packages/react-native-qnx/Libraries/Components/KeyboardAvoidingView/KeyboardAvoidingView.js`. The file header says QNX targets have no software keyboard or `Keyboard` native module, so the component is a pass-through `View`.

Wiring caveat. The Metro resolver replaces an upstream file only when the override sits at the same path under `Libraries` (`packages/metro-config-qnx/src/index.js:86-90`). Upstream `KeyboardAvoidingView` lives at `Libraries/Components/Keyboard/KeyboardAvoidingView.js`, and the QNX public entry requires exactly that path (`packages/react-native-qnx/Libraries/ReactNative/PublicAPI.js:117-119`). The override file sits at `Libraries/Components/KeyboardAvoidingView/KeyboardAvoidingView.js`. The relative paths differ, so I found no mechanism that makes the resolver pick the override for `KeyboardAvoidingView`. If that holds, the upstream component runs and everything in this page about a pass-through `View` applies only to code that imports the override path directly. No test imports either one: `tests/js/qnx-public-entry.test.mjs:58` only checks the export name. This is unresolved until someone resolves the module in Metro and confirms which file loads.

## Keyboard events on QNX

`PublicAPI.js:114-116` exports React Native's own `Keyboard` module unchanged. Upstream `Keyboard.js` builds its `NativeEventEmitter` with the iOS native module only when `Platform.OS` is `ios` (`Keyboard.js:73-77`), and passes `null` otherwise. On QNX that means a JS-only emitter. No file under `vnext/`, `native/` or `packages/` emits `keyboardDidShow`, `keyboardDidHide`, `keyboardWillShow`, `keyboardWillHide` or the frame-change events, so no event is ever delivered, and `Keyboard.isVisible()` stays false. Code in `packages/expo-router-qnx/src/BottomTabBar.js:132-133` subscribes to `keyboardDidShow` and `keyboardDidHide`, and the tests `tests/js/qnx-router-keyboard-space.test.mjs` and `qnx-router-tab-options.test.mjs` fire them from a mock `Keyboard`, not from the platform.

If the upstream component loads, it picks `Keyboard.addListener('keyboardDidShow' ...)` because `Platform.OS` is not `ios` (`KeyboardAvoidingView.js:207-221` upstream) and never receives a keyboard event, so it applies no avoidance either way.

## Platform behavior on QNX

Layout never changes when a text input gains focus. `Keyboard.dismiss` and frame events cannot drive layout. Hardware keyboards need no avoidance, and no on-screen keyboard exists in the evidence.
