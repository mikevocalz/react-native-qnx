## Behavior and limits

Renders children as a View and forwards the other View props; behavior, keyboardVerticalOffset, enabled and contentContainerStyle are ignored because no Keyboard module is wired. The override sits at the upstream path, so the Metro resolver selects it.

## Props

`KeyboardAvoidingView` is overridden in `packages/react-native-qnx/Libraries/Components/Keyboard/KeyboardAvoidingView.js`. The file header says QNX targets have no software keyboard or `Keyboard` native module, so the component is a pass-through `View`.

The Metro resolver replaces an upstream file only when the override sits at the same path under `Libraries` (`packages/metro-config-qnx/src/index.js`). Upstream `KeyboardAvoidingView` lives at `Libraries/Components/Keyboard/KeyboardAvoidingView.js`, and the override is at the same path, so the resolver selects it for the public entry and for direct imports. Until this was fixed the override sat at `Libraries/Components/KeyboardAvoidingView/`, a path React Native does not have, and a `qnx` bundle contained upstream's component. `tests/js/override-paths-match-upstream.test.mjs` now fails when any override path has no counterpart in the pinned `react-native`, and bundling the module with Metro for `qnx` produces the pass-through (upstream's `keyboardFrame` handling is absent from the bundle).

## Keyboard events on QNX

`PublicAPI.js:114-116` exports React Native's own `Keyboard` module unchanged. Upstream `Keyboard.js` builds its `NativeEventEmitter` with the iOS native module only when `Platform.OS` is `ios` (`Keyboard.js:73-77`), and passes `null` otherwise. On QNX that means a JS-only emitter. No file under `vnext/`, `native/` or `packages/` emits `keyboardDidShow`, `keyboardDidHide`, `keyboardWillShow`, `keyboardWillHide` or the frame-change events, so no event is ever delivered, and `Keyboard.isVisible()` stays false. Code in `packages/expo-router-qnx/src/BottomTabBar.js:132-133` subscribes to `keyboardDidShow` and `keyboardDidHide`, and the tests `tests/js/qnx-router-keyboard-space.test.mjs` and `qnx-router-tab-options.test.mjs` fire them from a mock `Keyboard`, not from the platform.

The override does not subscribe to keyboard events. React Native's own component would subscribe to `keyboardDidShow` because `Platform.OS` is not `ios`, never receive an event, and apply no avoidance either way.

## Platform behavior on QNX

Layout never changes when a text input gains focus. `Keyboard.dismiss` and frame events cannot drive layout. Hardware keyboards need no avoidance, and no on-screen keyboard exists in the evidence.
