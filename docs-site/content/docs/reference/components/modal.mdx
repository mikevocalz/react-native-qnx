## Props

`Modal` uses React Native's portable `ModalHostView` descriptor. The adapter maps it to a QML item named `RNQnxModal` (`vnext/src/fabric/ShadowViewMutationAdapter.cpp`, `vnext/src/views/qt/QtQuickItemFactory.cpp`). The adapter code that handles a Modal reads no Modal props: it marks the item as an overlay, sizes it to the surface root, and connects Escape to `onRequestClose`.

## Platform behavior on QNX

- The Modal is a full-screen overlay. Yoga places it in the tree, but on screen it covers the surface root from its top-left corner (`QtQuickMountingLayer.cpp`). Its shadow-node state is set to the root size, because the portable default of 0 by 0 laid the content out as nothing.
- Escape is the QNX counterpart of the Android back button. The QML item accepts the key, so it does not reach the covered app (`vnext/src/views/qt/QtModalQml.cpp`).
- Focus: opening a Modal takes active focus and remembers the previous focus item. Only the most recently opened Modal in a window reclaims focus and handles close. Closing restores the previous item. `docs/validation/pr159-modal-focus-2026-11-14.md` records 11 passing QtTest entries on a Linux offscreen host, with the bridge's close callback standing in for the Fabric emitter.
- Pi 400, run 2: the gallery Modal opened and closed after a synthetic `key esc` (`docs/evidence/pr149-pi400-run2-2026-11-19/README.md`).

## Unsupported or partial props

Props listed as accepted-no-effect or unsupported are not read by `ShadowViewMutationAdapter::applyModal` or `connectModalEvents`. A host that maps `ModalHostView` to a plain View has no `requestClose()` signal and keeps a modal that only closes from JavaScript (comment in `connectModalEvents`).

## Minimal example

```tsx
import React, { useState } from 'react';
import { Button, Modal, Text, View } from 'react-native';

export default function Screen() {
  const [open, setOpen] = useState(false);
  return (
    <View style={{ flex: 1 }}>
      <Button title="Open" onPress={() => setOpen(true)} />
      <Modal visible={open} onRequestClose={() => setOpen(false)}>
        <View style={{ flex: 1, backgroundColor: '#101820', padding: 24 }}>
          <Text style={{ color: 'white' }}>Press Escape or the button to close.</Text>
          <Button title="Close" onPress={() => setOpen(false)} />
        </View>
      </Modal>
    </View>
  );
}
```

## Known gaps

- Whether `onRequestClose` fires on the board is unconfirmed: the Pi 400 result rests on screenshots, with no log line.
- A physical keyboard was not tested; input was synthetic through Screen.
- `onShow`, `onDismiss`, `animationType` and `transparent` have no code behind them. A fix would need native event emission and prop handling.
- Focus behavior was tested on a Linux offscreen host, not on QNX.
