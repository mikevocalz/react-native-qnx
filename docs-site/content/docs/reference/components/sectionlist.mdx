## Props

`SectionList` is upstream React Native JavaScript with no QNX override (nothing for it under `packages/react-native-qnx/Libraries`). The QNX public entry exports it (`PublicAPI.js:27-29`). It renders `VirtualizedSectionList`, which renders `VirtualizedList` over a `ScrollView`.

A SectionList-specific host test exists. `sectionListRenders` (`tests/cpp/QtReactHostHostTest.cpp:1704-1745`) starts the surface `RNQnxSectionList`, whose app is `SectionListApp` (`apps/rn-playground/index.js:438-455`): two sections (two items and one item), `keyExtractor`, `renderSectionHeader`, `renderItem` and `onViewableItemsChanged`. It asserts that mounting reports no failures, that the surface has one root child, and that `onViewableItemsChanged` ran with `viewableItems.length >= 1`. It is recorded as `[PASS] sectionListRenders` in `docs/evidence/drawer-route-2026-11-13/drawer-input-host-test.txt:168` and in `drawer-input-negative-test.txt:169`. Both are offscreen host runs. The test does not scroll the list, does not assert header or footer content, and does not use sticky headers.

## Events

`onScroll`, `onLayout` and `onContentSizeChange` come from the same native sources as `FlatList` (`QtScrollBridge`, layout events). `onViewableItemsChanged` is tested once, as above. `onEndReached` uses the scroll metrics traced on the [FlatList](/docs/reference/components/flatlist) page and has no test in the repository. `onRefresh` never fires.

## Platform behavior on QNX

Sections flatten into a single `VirtualizedList` window, so windowing, batching and cell release behave as described on the [FlatList](/docs/reference/components/flatlist) page: scroll offsets arrive from the Qt Flickable, cell sizes come from `onLayout`, and the 50 ms batching period is real time because QNX timers are `QTimer`s. All limits of [ScrollView](/docs/reference/components/scrollview) carry over, including that `scrollToLocation` ends in a `ScrollView` command that ignores `animated`.

## Unsupported or partial props

- `stickySectionHeadersEnabled`: `SectionList.js:248-249` defaults it to `Platform.OS === 'ios'`, so it is off on QNX unless the app passes `true`. When true, `VirtualizedSectionList.js:189-200` builds `stickyHeaderIndices` from the section header positions and passes them down to the ScrollView, where sticky headers are JavaScript (`ScrollViewStickyHeader`, driven by an Animated scroll event and a `translateY` transform). The transform and `onScroll` pieces are host-tested separately. The Animated scroll-event driver and the combination are not. See [ScrollView](/docs/reference/components/scrollview).
- `scrollToLocation`: JavaScript. It computes a flat index, calls `scrollToIndex` on the inner list (`VirtualizedSectionList.js:140-169`), and ends in the `scrollTo` command, which ignores `animated`. No test calls it.
- `getItemLayout` and `SectionSeparatorComponent`: JavaScript with no native dependency; no test.
- `inverted`: `scaleY: -1` is dropped by the transform reader, as described on the [FlatList](/docs/reference/components/flatlist) page.
- Anything depending on ScrollView props with no native read (`scrollEnabled`, `pagingEnabled`, `bounces`, scroll indicators, `contentInset`, `refreshControl`).

## Minimal example

```tsx
import React from 'react';
import { SectionList, Text, View } from 'react-native';

const sections = [
  { title: 'Fruit', data: ['Apple', 'Pear', 'Plum'] },
  { title: 'Vegetables', data: ['Leek', 'Kale', 'Beet'] },
];

export default function App() {
  return (
    <SectionList
      style={{ flexShrink: 0, height: 240 }}
      sections={sections}
      keyExtractor={(item) => item}
      renderSectionHeader={({ section }) => (
        <View style={{ height: 28, backgroundColor: '#dddddd', justifyContent: 'center' }}>
          <Text>{section.title}</Text>
        </View>
      )}
      renderItem={({ item }) => (
        <View style={{ height: 30, justifyContent: 'center' }}>
          <Text>{item}</Text>
        </View>
      )}
    />
  );
}
```
