## Behavior and limits

Opt-in (RNQNX_ENABLE_QT_VIDEO, needs the Qt Multimedia add-on). Qt Multimedia FFmpeg backend, software decode, frames in the Qt Quick scene graph. Props: source, paused, muted, volume, rate, repeat, resizeMode, poster, controls, fullscreen; events: onLoad, onProgress, onEnd, onError, onBuffer, onSeek, onFullscreen; ref: seek, play, pause. Pi 400 (2026-11-13, branch feat/qt-video, no commit SHA in the receipt): 480x270 H.264/AAC clip played, seek, pause, play, end and bad-URL error reached JavaScript; after FFmpeg was rebuilt with OpenSSL 3, an https clip (960x540, 5.06 s) played 143 frames in 5.0 s. No hardware decode. A host test (tests/native/qt-video) and JS tests (tests/js/qt-video.test.mjs) exist; the host-renderer workflow sets RNQNX_ENABLE_QT_VIDEO on its ON leg. Control-bar taps and fullscreen not exercised. The 2026-11-19 Pi 400 builds had QtVideo OFF (the Video and Audio cards read "QtVideo is not in this build"), so they say nothing about it. The react-native-video 7 beta cannot load on the pinned Nitro v1; a JavaScript API subset exists but has not run.

## Props

`QtVideo` is QNX-only. `packages/react-native-qnx/qt/index.js:42-91` wraps the Fabric component `QnxQtVideo`, declared in `qt/QtVideoNativeComponent.ts` and typed in `qt/index.d.ts`. `vnext/src/fabric/QtVideoBridge.cpp:44-74` forwards each changed prop to `native/qt/video/QtVideoItem.cpp`, which sets properties on `QnxVideo.qml`.

**Fullscreen.** The prop sets `QnxVideo.qml`'s `fullscreen` property (`QtVideoItem.cpp:105`). The only effect there is the border of the bar's fullscreen button turning from white to the accent color (`QnxVideo.qml:234`). A click on that button emits `fullscreenToggled(!fullscreen)` (`:239`), which reaches JavaScript as `onFullscreen` (`QtVideoBridge.cpp:39-41`). Nothing changes the property in response, so the app must feed the value back. No code resizes the item or window for it: searches of `vnext`, `native` (including `native/window-chrome`), `packages` and `apps` for window-state calls found `showFullScreen` only for the runner's `--fullscreen` option (`vnext/probes/playground/main.cpp:797, 941`), which does not read this prop. So `fullscreen` is a flag plus an event, and the app has to do the resize.

## Events

Handlers receive the payload directly (`index.js:76`). `onLoad` has `duration, width, height, audioDevice`; `onProgress` has `currentTime, playableDuration` every 250 ms while playing (`QnxVideo.qml:150-155`); `onEnd` has none; `onError` has `message, code`; `onBuffer` has `isBuffering`; `onSeek` has `currentTime, seekTime`; `onFullscreen` has `fullscreen`. All are connected in `QtVideoBridge.cpp:15-42`. The ref has `seek`, `play`, `pause`. `playsSeeksAndEnds` and `reportsBadSource` cover load, seek, end and error on a host with a working backend, and skip otherwise.

## Platform behavior on QNX

Playback uses Qt Multimedia with the FFmpeg backend, software decode, and frames are drawn in the Qt Quick scene graph. The component exists only if the host is built with `RNQNX_ENABLE_QT_VIDEO=ON` (default OFF in `cmake/RnqnxQtNative.cmake`) and the Qt Multimedia add-on. Without it, rendering throws "QtVideo is unavailable" because the view manager `QnxQtVideo` is missing. On the Pi 400 on 2026-11-13, a 480x270 H.264/AAC clip played, with seek, pause, play, end and a bad-URL error reaching JavaScript. An https clip played after FFmpeg was rebuilt with OpenSSL 3. Source: `docs/evidence/media-2026-11-13.md`. Subtitles, audio-track selection, HLS and DASH playlists and picture-in-picture have no props or code (`docs/getting-started/media.md`). Hardware decode is not used.

## Minimal example

```tsx
import React from 'react';
import { QtVideo } from '@rn-qnx/react-native-qnx/qt';

export default function Player() {
  return (
    <QtVideo
      style={{ width: 480, height: 270 }}
      source="http://192.168.2.1:8765/rnqnx-test-clip.mp4"
      controls
      onLoad={(e) => console.log('loaded', e.duration, e.width, e.height)}
      onError={(e) => console.log('error', e.code, e.message)}
    />
  );
}
```

Build the host with `-DRNQNX_ENABLE_QT_VIDEO=ON`. See [Qt tiers](/docs/reference/qt-tiers).

## Known gaps

- Control-bar taps and the fullscreen toggle were not exercised on the board (`docs/evidence/media-2026-11-13.md`).
- The 2026-11-19 Pi 400 builds had QtVideo off, so they say nothing about it.
- Host column is unverified: `tests/native/qt-video` and `tests/js/qt-video.test.mjs` exist, but no run of them is recorded, and the playback tests skip on a Qt build without a working backend.
- `rate`, `poster`, `resizeMode`, `controls` and `fullscreen` have no test at any level.
- `packages/react-native-qnx/video` (`useVideoPlayer`, `VideoView`) has not run on a device and is not aliased in Metro. The upstream `react-native-video` 7 beta cannot load on the pinned Nitro v1.
