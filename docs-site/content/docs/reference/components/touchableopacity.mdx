## Behavior and limits

Mounts through the responder system and uses NativeAnimated opacity. Responder coverage comes from Pressable.

## Props

`TouchableOpacity` has no QNX override. It is React Native's component, built on `Pressability` with an `Animated.View` (`TouchableOpacity.js:168-173,232`). No file under `tests/` renders `TouchableOpacity` directly. `Button` renders it, and `buttonMounts` only checks that the mount succeeds (`tests/cpp/QtReactHostHostTest.cpp:2088-2116`).

Native touch path: only Fabric `onTouchStart`, `onTouchMove`, `onTouchEnd` and `onTouchCancel` reach React (`vnext/src/fabric/QtTouchDispatcher.cpp:227-247,280-360`). There is no hover or pointer enter and leave event, and hit testing uses item geometry (lines 141-225), so a press cannot start outside the view's box. Long-press and delay timing, `hitSlop` and `pressRetentionOffset` regions are computed in JavaScript by `Pressability` (`Pressability.js:464-478,800-867`) using `setTimeout` and a shadow-tree `measure`. The only press test is the `Pressable` probe (`tests/cpp/QtPressableProbe.cpp`), which covers press in, out, press, cancel, deactivation, disabled, unmount and remount, not long press or regions.

## Platform behavior on QNX

React's JS responder logic decides when a press starts and ends. The dimming animation runs through NativeAnimated. If the backend were not connected, the opacity change would not reach the Qt item; No evidence found for that case, and the backend is created unconditionally at the line above.
