Four statuses appear in these docs. No page uses "seamless" or similar wording for a feature without a device-verified row and the commit behind it.

| Status | Meaning |
| --- | --- |
| Device-verified | A receipt shows it running on the custom Pi 400 image. The scenario is named. |
| Host-tested | A host test covers it, run in CI or locally. No device receipt. |
| Untested | No claim either way. |
| Not supported | Not implemented. |

"Host-tested" in this repository means a hosted CI job builds and runs the test on Linux. The repository does not use a "Tier A" label for it.

## Not proven

Pinch, rotation, multi-pointer, 1920x1080 output beyond the Hello World capture (the 2026-11-19 runs used 1024x768), Video and Audio, a real USB keyboard hold, a stock Pi 4, and all 11 release gates. See [known gaps](/docs/reference/known-gaps) and [release gates](/docs/reference/release-gates).
