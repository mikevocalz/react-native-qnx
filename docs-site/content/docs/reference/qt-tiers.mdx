The rule comes from [`docs/build-qt-modules.md`](https://github.com/mikevocalz/react-native-qnx/blob/main/docs/build-qt-modules.md): add one module at a time, with a justification, a licence check and QNX size and build-time data. Development follows the open-source Qt path ([ADR-0013](https://github.com/mikevocalz/react-native-qnx/blob/main/docs/adr/0013-open-source-qt.md)). No paid Qt subscription is a prerequisite. Licence status for each module is in [ADR-0011](https://github.com/mikevocalz/react-native-qnx/blob/main/docs/adr/0011-qt-module-licensing.md).

Host builds require Qt 6.11.1 or newer (`find_package(Qt6 6.11.1 ...)` in `CMakeLists.txt`). The QNX runtime is built from public Qt 6.12.0 sources (`docs/packaging.md`, "Public-source Qt 6.12.0 for QNX"). The size and build-time columns in the source table read TBD, so no QNX size measurement is published.

## Tiers

- **Tier 0**: always on. Qt Core, Gui, Qml and Quick, LGPLv3 or GPLv2.
- **Tier 1**: component-backing. Added when a component needs the module. LGPLv3 or GPLv2.
- **Tier 2**: evaluate per need. Most are LGPLv3 or GPLv2. Quick 3D, Graphs, Lottie, Quick Timeline, Quick 3D Physics, Canvas Painter, HTTP Server and the Qml compiler are **GPLv3 only** in the open-source distribution. Qt PDF is an extension or commercial module.
- **Excluded**: `QtQuickLayouts` (conflicts with Yoga), `QtWebEngine` and `QtWebView` (no QNX backend or Chromium cross-build scope), `QtVirtualKeyboard` (GPLv3-only, needs a product decision).

Notes that qualify the table:

- The base host list is exactly `set(RNQNX_QT_HOST_MODULES Core Gui Qml Quick)` at `CMakeLists.txt:322`. Network, WebSockets, Svg and Multimedia are found by their own CMake files, not by that list.
- Network was added as a deliberate direct link rather than a transitive one (`docs/build-qt-modules.md`, "Image-loader Network dependency"). Its QNX size and build-time delta are TBD, and the doc states target acceptance is still blocked on those.
- The QNX binary-size delta of WebSockets is on record for one file: `libQt6WebSockets.so.6.12.0` is 333,792 bytes for aarch64le. Cross-build time was not timed.
- The `rnsvg` target (`native/qt/rnsvg/CMakeLists.txt`) does not link `Qt6::Svg`. A QNX runtime without the Svg module still renders everything except SVG `Image` sources.
- Multimedia was built as an add-on for the Pi 400 on 2026-11-13 (`docs/evidence/media-2026-11-13.md`). The 2026-11-19 Pi 400 builds had QtVideo OFF (`docs/component-support.md`, `QtVideo` row), so they do not exercise it.
- `ImageFormats` stays a plugin build. The deployed file list of the Pi 400 run 2 holds only `plugins/imageformats/libqsvg.so` in that directory, so the receipt does not record which decoder produced the animated GIF and WebP frames (`docs/build-qt-modules.md`).

## Restricted runtime subset

The public-source QNX build lists Core, Gui, Network, OpenGL, Qml, QmlMeta, QmlModels, QmlWorkerScript, Quick and QuickShapes, plus the QNX QPA plugin `plugins/platforms/libqqnx.so`. `qtshadertools` is a host build tool. Source: `docs/packaging.md`. Every audited Qt module file offers `LGPL-3.0-only`, and no file is GPL-only.

See also [module matrix](/docs/reference/module-matrix), [licensing and packaging](/docs/explanation/licensing-and-packaging) and [requirements](/docs/reference/requirements).
