This page lists configuration keys with the file that reads them. Everything here comes from source files in the repository, read on 2026-11-19. None of the keys were exercised by a build for this page. For environment variables, see [environment variables](/docs/reference/environment-variables). For Metro, see the [Metro config reference](/docs/reference/metro-config). For command options, see the [CLI reference](/docs/reference/cli).

## App config

Keys the CLI reads from the resolved Expo config. Identity keys can also be set as options of the config plugin `@rn-qnx/expo-qnx-config-plugins`. Plugin options win over values already in `expo.extra.rnqnx` (`packages/expo-qnx-config-plugins/index.js`, function `withQnxProject`).

### Identity

| Key                                                             | Type   | Default                        | Required | Meaning                                                                                                                                                                                              | Source                                     |
| --------------------------------------------------------------- | ------ | ------------------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| `expo.name`                                                     | string | none                           | yes      | Display name. 1 to 128 characters, no control characters, no leading or trailing whitespace. Window title and About name.                                                                            | `prepare-native.mjs` `validateAppIdentity` |
| `expo.extra.rnqnx.appId`, plugin option `appId`                 | string | none                           | yes      | Reverse-DNS ID, for example `org.example.notes`. At most 255 characters, letters, digits, `_` and `.` only, at least two dot-separated parts, each starting with a letter, and no `.desktop` suffix. | `prepare-native.mjs`                       |
| `expo.extra.rnqnx.componentName`, plugin option `componentName` | string | `main`                         | no       | Name registered with `AppRegistry`. ASCII letters, digits and `_`, starting with a letter, 1 to 128 characters.                                                                                      | `prepare-native.mjs`                       |
| `expo.extra.rnqnx.shortName`, plugin option `shortName`         | string | `expo.name`                    | no       | Launcher tile label. Same character rules as the name, plus no invisible format characters and at least one visible character. At most 128 characters.                                               | `app-identity.mjs` `resolveTileLabel`      |
| `expo.icon`                                                     | string | `template/qnx/assets/icon.png` | no       | Project-relative path such as `./assets/icon.png` to a square PNG, 1024 to 8192 pixels per edge, at most 32 MiB. With none set, the default icon is used and a notice is printed.                    | `app-identity.mjs` `validateIconSource`    |
| `expo.extra.rnqnx.icon`, plugin option `icon`                   | string | none                           | no       | Same as `expo.icon`, for QNX only. Wins over `expo.icon`.                                                                                                                                            | `app-identity.mjs`                         |

Plugin option values `appId`, `componentName`, `shortName` and `icon` must be nonempty strings, else `@rn-qnx/expo-qnx-config-plugins option <key> must be a nonempty string.`

The CLI measures the tile label only when a launcher profile exists for the platform. For `qnx` the source says `No QNX launcher is defined in this repository or the QNX SDP, so there is no label box to measure.` `project doctor` therefore reports the `tile-label` check as `not-checked` for QNX. The help text's statement that the label "must fit the target launcher on one line" has no measured QNX box behind it.

### Plugin-only options

These options go on the plugin entry. They are written to `expo.extra.rnQnx` (capital Q), not `extra.rnqnx`.

| Option             | Type                    | Default                                  | Meaning                                                   | Source                                           |
| ------------------ | ----------------------- | ---------------------------------------- | --------------------------------------------------------- | ------------------------------------------------ |
| `targetArch`       | `'aarch64'`, `'x86_64'` | `aarch64`                                | Target architecture recorded for Expo module autolinking. | `expo-qnx-config-plugins/index.js`, `index.d.ts` |
| `autolinkingJson`  | string                  | `build/generated/expo-qnx-modules.json`  | Path recorded for the autolinking JSON.                   | same                                             |
| `autolinkingCMake` | string                  | `build/generated/expo-qnx-modules.cmake` | Path recorded for the autolinking CMake file.             | same                                             |

`expo.extra.rnqnx.platforms` (an array, written as `["qnx"]` by `project create`) has no reader in `packages/react-native-qnx-cli/src`. No evidence found for a consumer of that key.

Example plugin entry, as `project add-qnx` writes it into `app.json`:

```json
["@rn-qnx/expo-qnx-config-plugins", { "appId": "org.example.notes", "componentName": "main" }]
```

### Window

Key path: `expo.extra.rnqnx.window`, or plugin option `window`. Source: `resolveQnxWindow` in `packages/expo-qnx-config-plugins/index.js`, repeated in `window-descriptor.mjs`, `cmake/RnqnxConsumerApp.cmake` and `rnqnx::window::parseWindowChromeConfig`. An unknown key, a `null` or a wrong type throws, so a typo fails at prebuild.

| Key                          | Type                              | Default in the plugin | Default when read from `native-app.json` | Meaning                                                         |
| ---------------------------- | --------------------------------- | --------------------- | ---------------------------------------- | --------------------------------------------------------------- |
| `window.controls`            | `'macos'`, `'windows'`            | `macos`               | `macos`                                  | Title bar button layout.                                        |
| `window.titleBarStyle`       | `'default'`, `'hidden'`, `'none'` | `default`             | `default`                                | `none` draws no title bar. `--window-chrome` fails with `none`. |
| `window.initialSize`         | `{ width, height }`               | unset                 | unset                                    | Exactly two keys, each an integer from 1 to 16384.              |
| `window.unavailableControls` | `'hide'`, `'disable'`             | unset                 | `hide`                                   | A control the platform cannot run is left out or drawn inert.   |

A `native-app.json` with no `window` key predates the field and is read as `controls: macos`, `titleBarStyle: none`, `unavailableControls: hide` (`window-descriptor.mjs`). The title bar is drawn only in a build made with `RNQNX_ENABLE_WINDOW_CHROME=ON`; see [window chrome](/docs/how-to/window-chrome).

## native-app.json

Generated by `project prepare-native` at `build/<platform>/native-app.json`. Do not edit it: CMake rechecks the bundle and icon hashes, and `prepare-native` refuses to overwrite a descriptor that differs (`prepare-native.mjs`, `cmake/RnqnxConsumerApp.cmake`).

| Key             | Type   | Meaning                                                                                                                                |
| --------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `schemaVersion` | number | `1`.                                                                                                                                   |
| `generatedBy`   | string | `react-native-qnx/prepare-native-v1`. CMake rejects another value.                                                                     |
| `appId`         | string | From the identity above.                                                                                                               |
| `displayName`   | string | `expo.name`.                                                                                                                           |
| `componentName` | string | From the identity above.                                                                                                               |
| `platform`      | string | `qnx`.                                                                                                                                 |
| `bundle`        | string | Absolute path of the bundle, at most 256 MiB. A real QNX build needs a `.hbc` file.                                                    |
| `bundleSha256`  | string | SHA-256 of the bundle. CMake fails with `Consumer bundle hash changed; prepare its configuration again` if it differs.                 |
| `window`        | object | The resolved window, see above.                                                                                                        |
| `nitroModules`  | array  | Present only when the app has Nitro modules. At most 64 entries.                                                                       |
| `expoModules`   | array  | Present only when the app has Expo modules. At most 64 entries.                                                                        |
| `expoConfig`    | object | Present only with `expoModules`. The resolved Expo config without keys that start with `_`, at most 16 KiB as compact JSON.            |
| `shortName`     | string | Tile label.                                                                                                                            |
| `icon`          | object | `source`, `sha256`, and `sizes`, a list of `{ size, path, sha256 }` for sizes 16, 24, 32, 48, 64, 96, 128, 192, 256, 512.              |
| `labelFit`      | object | Label measurement. Its `widthPx` and `fallbackCodePoints` depend on the host's Qt and are left out of the stale-descriptor comparison. |

Each `nitroModules` and `expoModules` entry has exactly these string keys: `package`, `version`, `root`, `cmakeLists`, `target`, `initializer` (`cmake/RnqnxConsumerApp.cmake`).

## Native module declarations

A direct dependency of the app declares a native module for QNX in its own `package.json`. `prepare-native` reads JSON only and runs no package code (`packages/react-native-qnx-cli/src/nitro-modules.mjs`). See [Nitro modules](/docs/how-to/nitro-modules).

```json
{
  "react-native-qnx": {
    "nitro": {
      "platforms": ["qnx"],
      "cmakeListsPath": "qnx/CMakeLists.txt",
      "target": "my_module",
      "initializer": "my::ns::registerQnxHybridClasses"
    }
  }
}
```

The path, target and function in this example are placeholders, not a real package.

| Key                | Type     | Rule                                                                                                                        |
| ------------------ | -------- | --------------------------------------------------------------------------------------------------------------------------- |
| `react-native-qnx` | object   | Allowed keys: `nitro` and `expo`. Both use the same four fields.                                                            |
| `.platforms`       | string[] | Nonempty, no repeats. Only `qnx` is supported; another value throws.                                                        |
| `.cmakeListsPath`  | string   | Package-relative path to a file named `CMakeLists.txt`, with no `..`, `.`, empty segment, backslash or CMake metacharacter. |
| `.target`          | string   | CMake target name, 1 to 128 characters, `^[A-Za-z_][A-Za-z0-9_.+-]*$`, not starting with `rnqnx_`.                          |
| `.initializer`     | string   | A C++ function name such as `ns::fn`, at most 256 characters.                                                               |

## CMake presets

File: `CMakePresets.json`, `version` 6, `cmakeMinimumRequired` 3.31.9. All configure presets use the Ninja generator and the binary directory `build/<preset name>`, except `qnx-pi`, which uses `build/qnx-pi4`.

| Configure preset      | Toolchain file                              | `CMAKE_BUILD_TYPE` | Other cache variables                                                                                                                                      | Condition                 |
| --------------------- | ------------------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| `macos-host-debug`    | none                                        | Debug              | `CMAKE_C_COMPILER=clang`, `CMAKE_CXX_COMPILER=clang++`, `BUILD_TESTING=OFF`                                                                                | host is Darwin            |
| `macos-host-release`  | none                                        | Release            | same                                                                                                                                                       | host is Darwin            |
| `macos-host-tests`    | none                                        | Debug              | clang compilers, `BUILD_TESTING=ON`, `RNQNX_ENABLE_HOST_SANITIZERS=ON`                                                                                     | host is Darwin            |
| `linux-host-debug`    | none                                        | Debug              | `BUILD_TESTING=OFF`                                                                                                                                        | host is Linux             |
| `linux-host-tests`    | none                                        | Debug              | `BUILD_TESTING=ON`, `RNQNX_ENABLE_HOST_SANITIZERS=ON`                                                                                                      | host is Linux             |
| `qnx-aarch64-debug`   | `vnext/cmake/qnx-aarch64le.toolchain.cmake` | Debug              | `BUILD_TESTING=OFF`                                                                                                                                        | none                      |
| `qnx-aarch64-release` | `vnext/cmake/qnx-aarch64le.toolchain.cmake` | Release            | `BUILD_TESTING=OFF`                                                                                                                                        | none                      |
| `qnx-x86_64-debug`    | `cmake/toolchains/qnx-8.0.cmake`            | Debug              | `BUILD_TESTING=OFF`, `QNX_TARGET_ARCH=x86_64`                                                                                                              | none                      |
| `qnx-x86_64-release`  | `cmake/toolchains/qnx-8.0.cmake`            | Release            | same                                                                                                                                                       | none                      |
| `qnx-pi4`             | `vnext/cmake/qnx-aarch64le.toolchain.cmake` | Debug              | `BUILD_TESTING=OFF`, `RNQNX_G0_PROBE_ONLY=ON`. Description: a configure or build is not a passed gate until the binary runs on the Pi.                     | none                      |
| `qnx-pi`              | `vnext/cmake/qnx-aarch64le.toolchain.cmake` | Debug              | same as `qnx-pi4`. Description: runtime proof still requires the physical QSTI target.                                                                     | none                      |
| `linux-host-renderer` | none (inherits `linux-host-tests`)          | Debug              | adds `RNQNX_REQUIRE_FULL_HOST_RENDERER=ON`, `RNQNX_BUILD_HERMES=ON`, `RNQNX_FETCH_REACT_NATIVE_DEPS=ON`, clang compilers, `CMAKE_CXX_SCAN_FOR_MODULES=OFF` | host is Linux (inherited) |

Build presets exist for every configure preset above with the same name. `qnx-pi4` and `qnx-pi` build only the target `rnqnx_g0_cxx20_probe`. `linux-host-renderer` sets `jobs` to 2. Test presets exist for `macos-host-tests`, `linux-host-tests` (both with `outputOnFailure`) and `linux-host-renderer` (`noTestsAction` `error`, `timeout` 180 seconds).

`pnpm qnx configure-qnx` and `build-qnx` select `qnx-<arch>-<config>`; `project build-native` selects `qnx-aarch64-debug` or `linux-host-renderer`.

## Runner manifest

JSON at the URL given to `runner list` or `runner fetch` (`packages/react-native-qnx-cli/src/runner.mjs`, `validateRunnerManifest`).

| Key                         | Type     | Rule                                                                                                       |
| --------------------------- | -------- | ---------------------------------------------------------------------------------------------------------- |
| `schema`                    | string   | Must be `rnqnx-runner-manifest/v1`.                                                                        |
| `publishedAt`               | string   | An ISO date.                                                                                               |
| `runners`                   | array    | At most 256 entries, unique `id`s.                                                                         |
| `runners[].id`              | string   | `^[a-z0-9][a-z0-9.-]{0,127}$`.                                                                             |
| `runners[].target`          | string   | One of `qnx-aarch64-pi400`, `macos-arm64`, `macos-x86_64`, `linux-x86_64`, `linux-aarch64`.                |
| `runners[].kind`            | string   | `development` or `standalone`. `runner fetch` selects only `development`.                                  |
| `runners[].format`          | string   | `tar.gz`.                                                                                                  |
| `runners[].sha256`          | string   | 64 lowercase hex characters.                                                                               |
| `runners[].size`            | integer  | 1 to 2 GiB.                                                                                                |
| `runners[].url`             | string   | https, or http to loopback. No credentials.                                                                |
| `runners[].versions`        | object   | Keys `reactNativeQnx`, `reactNative`, `hermes`, `qt`, `sdp`. `sdp` may be `null` for non-QNX targets only. |
| `runners[].targetLibraries` | string[] | Required for `qnx-` targets. Up to 256 distinct shared-library names.                                      |
