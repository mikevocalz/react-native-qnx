## Reading the matrix

The projects fall into two groups. Spark and Expo Desktop are young, document by capability and omit reference material such as a CLI page or changelog. The Microsoft sites are mature, so they carry a CLI reference, release process pages and, for Windows, versioned docs and a native API reference. This site carries more reference than the first group because every status claim has to cite a commit. It has less API depth than react-native-windows.

Three things only this site has: a status and a commit SHA on every component row, a verification log of every documented command, and the pages being generated from `docs/component-support.json` and git, so they cannot drift from the data.

## Closed since the first pass

- **Per-function native API reference.** [Native API](/docs/reference/native-api) lists every declaration in the public C++ headers and the Nitro specs, with the doc comment found above it and a link to its line. Headers that are not public are listed with the CMake reason and are not expanded. `npm run api:check` fails when a page differs from the headers.
- **Versioned docs.** The header has a version selector. It lists `latest` and the frozen copies in `docs-site/versions.json`. The list of copies is empty because the repository has no tag, so no release was invented. [Versioning and support](/docs/explanation/versioning-and-support#proposed-versioning-scheme) proposes the scheme, and [Contributing](/docs/contributing#snapshot-the-docs-at-a-release-tag) has the procedure for adding a copy.
- **Samples gallery.** [Gallery](/docs/gallery) shows the screenshots and images kept under `docs/evidence`, each with what its receipt says produced it.
- **Architecture decision pages.** ADR 0003, 0012 and 0016 now have pages like the other records, with a section on where each record no longer matches the tree.

## Left open

- **Search quality.** The search index is Fumadocs' static index. It has not been compared against the others, and none of the other sites could be tested interactively.
- **Native API depth.** The reference is as good as the header comments. Declarations with no comment say so. It does not cover the JavaScript surface of the packages, which [Nitro modules](/docs/how-to/nitro-modules) and the [module reference](/docs/reference/module-matrix) describe.
- **Gallery coverage.** Two images have no receipt that names them. The gallery index lists them.
