These are working assumptions for page order, not research findings. No user interviews back them. Replace them when real readers tell you otherwise.

| Reader                                       | Goal                                 | Top tasks                                              | Where they start                                                                                 |
| -------------------------------------------- | ------------------------------------ | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Expo developer with a Mac                    | See whether their app can target QNX | Create an app, bundle it, check which components work  | [Quick start](/docs/tutorials/quick-start), [component matrix](/docs/reference/component-matrix) |
| Embedded engineer with a QNX SDP and a board | Run an app on hardware               | Check the toolchain, build, deploy, iterate with Metro | [First device run](/docs/tutorials/first-device-run), [debugging](/docs/how-to/debugging)        |
| Native or Nitro module author                | Add a native API                     | Learn the threading rules, follow the API policy       | [Threading](/docs/explanation/threading), [Nitro modules](/docs/how-to/nitro-modules)            |

## Page types

Pages follow [Diataxis](https://diataxis.fr). A tutorial teaches by doing and has one path. A how-to solves one task. Reference lists facts without argument. Explanation gives background. A page does one of these.
