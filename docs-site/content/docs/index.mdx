React Native QNX runs a React Native 0.88 app on QNX SDP 8.0.5. Fabric and Hermes execute the JavaScript, Yoga lays out the views, and a Qt Quick mounting layer draws them through QNX Screen. The project is experimental and pre-v1: all eleven release gates in `docs/releases/v1-readiness.json` are pending (see [release gates](/docs/reference/release-gates)).

## What is verified

Every device result comes from one physical Raspberry Pi 400 running a custom BCM2711 image of QNX 8.0.5 (the board's `uname` reports `QNX qnxpi 8.0.0 2026/06/05`). No stock Pi 4 has run anything. The scoped results below come from the 2026-11-19 runs, recorded under `docs/evidence`, on a 1024x768 display.

| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Earlier scoped receipts cover `View`, `Text`, `TextInput` and `Pressable`. The [component matrix](/docs/reference/component-matrix) lists every component with its host and Pi 400 status and the commit that last changed its evidence. A host result (the Qt Quick renderer tests and the hosted CI workflows) shows that code builds and renders on macOS or Linux. It says nothing about QNX.

## What is not verified

- Pinch, rotation and any multi-pointer gesture. The input injector sends one pointer.
- 1920x1080 output beyond the Hello World capture. The 2026-11-19 runs used 1024x768 because the monitor's EDID was unreadable.
- Video and audio in the 2026-11-19 runs. Those builds set `RNQNX_ENABLE_QT_VIDEO=OFF`. An earlier scoped receipt for `QtVideo` exists in `docs/evidence/media-2026-11-13.md`, and it has not been repeated on the current gallery.
- A held key on a real USB keyboard. The key hold run used synthetic Screen events.
- A stock Pi 4.
- All eleven release gates, including the QNX cross-build check, which no workflow performs yet.

See [status and limits](/docs/reference/status) and [known gaps](/docs/reference/known-gaps).
