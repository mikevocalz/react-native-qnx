This gallery shows real captures from `docs/evidence/`. Each one carries a caption block with five fields: what it shows, the build, the device, the resolution and the receipt. The captions repeat what the receipt says or what can be read off the image. When a receipt does not give a field, the caption says "not recorded in the receipt" or names the gap. Nothing here is stock imagery, and every image is copied unchanged.

## Counts

The evidence folder holds 170 image files: 162 PNG, 6 JPEG, 1 GIF and 1 WebP. It holds no BMP files and no video files, so no format conversion was needed. Every image is copied unchanged, with the same relative path, to `/evidence/` on this site.

## How to read a caption

- **Shows** is the receipt's own description where the receipt gives one. Otherwise it is a plain description of what is visible, and the caption says so.
- **Build** names the commit, branch, flags and artifact hashes the receipt records. Where the receipt names no commit, the caption says so. The "Added to the repository" row is the commit that first added the image file. It is not the build commit.
- **Device** is the board or host the receipt names. A host run is never presented as a device run.
- **Resolution** is the pixel size of the image file, read with `sips`, plus whatever the receipt says about the display or window size. The file size and the display size can differ, because some captures are crops or downscaled copies.
- **Receipt** links to the file on GitHub. Receipts that are text logs sit next to the images in `docs/evidence`.

Captures from the Pi 400 come from one custom BCM2711 QNX 8.0.5 image. No capture comes from a stock Pi 4. See the [verification log](/docs/reference/verification-log) and the [status page](/docs/reference/status) for what each result does and does not qualify.

## Duplicates and animation

Several files in one run are byte-identical to each other, for example the stock desktop captures and the SVG host frames. The caption of the later file says which file it duplicates. The one animated GIF and the one animated WebP are 64x48 test inputs. They are not device captures. Animated behaviour on the device is shown as separate still frames taken a moment apart.
