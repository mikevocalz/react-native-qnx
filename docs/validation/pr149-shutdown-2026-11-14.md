Fabric, Hermes, Qt Quick and the existing platform ownership order remain.
All three feature switches continue to default OFF.

`QtUiThread::post` previously read a receiver whose destruction could race
with enqueueing. `stop` could also return to a second caller while the first
caller was still joining. `QtFrameBridge::postToGui` used an atomic raw
receiver pointer, which did not keep the QObject alive. A frame batch already
queued on the UI thread could deliver callbacks after shutdown.

Admission mutexes now protect receiver lookup through queued invocation and
closing admission. Receiver destruction, callback execution and joining happen
outside these mutexes. `std::call_once` makes all stop callers wait for the
same completed join. UI jobs check closed admission before running; frame
batches check shutdown before taking callbacks and before each callback.
An already running callback may finish. The bridge still must outlive the
joined UI thread, as the existing `QtWorkletsPlatform::shutdown` order does.
The patch does not move React JS off the GUI thread.
