# Image fetch I/O, cache recovery and redirects

Base: `df434d5`, PR 159. This slice changes QtImageFetcher and ImageDiskCache;
it preserves the Fabric/Qt Quick renderer, image limits and six-load shared
queue. No dependency, window configuration, Nitro registration or premium
component changes.

## Behavior and ownership

File/data reads, disk reads, cached-image validation and disk writes now run
on a QThreadPool. All loads, including local/cache work, take one queue slot.
Network operations and completion callbacks remain on the fetcher's owner
thread. Workers capture plain request/result values, a retained cache handle
and a cancellation token. They do not capture JSI promises or application
callbacks. Cancelling/destroying the fetcher releases callbacks on its owner
thread and suppresses later worker completion. An already-running file
operation can finish; cancellation does not roll back a cache write.

ImageDiskCache copies share an immutable directory, mutex and atomic budget.
This keeps worker storage alive after the original handle is destroyed and
avoids a filesystem lock in the budget getter. A bounded read checks the file
size before allocation and removes oversized entries. Cached bytes are decoded
at a small target on the worker; corrupt entries are removed and HTTP is tried
once. This is not a cross-process locking or HTTP revalidation cache.

Fetchers share one QNetworkAccessManager per owner thread. Requests keep
automatic cookie loading/saving and authentication reuse disabled. Redirects
retain one queue slot and deadline, allow at most five hops, reject non-HTTP(S),
userinfo and HTTPS-to-HTTP targets, and drop all caller headers on an origin
change. Cache-Control private/no-store across any hop prevents cache storage.
