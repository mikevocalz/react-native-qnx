# Component Support

What actually works, on the macOS development host, driven by a real React
Native bundle and verified by reading pixels back from a rendered frame.
Nothing in this table has been cross-compiled for QNX or run on a Raspberry
Pi 4.

Legend: ✅ works and is covered by a host test · ⚠ partial, with the limit named
· ❓ untested, no claim either way · ❌ not implemented.

## Components

| Component                  | Status | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `View`                     | ⚠      | Mounts, lays out, and paints background, corner radius, and opacity.                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `Text`                     | ⚠      | Renders with string, font size, colour, mixed styling, wrapping, and `numberOfLines` with `elide`. Inline attachments are not supported by Qt Quick `Text` and are reported as zero-sized, matching React Native's generic fallback. Covered by a host test.                                                                                                                                                                                                                                 |
| `Image`                    | ✅     | Renders from `data:` URIs through this platform's image provider. `resizeMode` maps to QML `Image.fillMode`. `defaultSource` is used as the image URI when no primary source is provided. `onLoadStart`, `onLoad`, `onLoadEnd`, and `onError` events are wired. `Image.getSize` works for `data:`, `file:`, `qrc:`, and absolute paths; `Image.prefetch` is a no-op stub. Bundler assets (`require('./x.png')`) resolve through `Image.resolveAssetSource` and are covered by a host test. |
| `ScrollView`               | ✅     | Mounts as a Qt `Flickable` that clips and scrolls. All scroll lifecycle events reach JavaScript with current `velocity` and `targetContentOffset`. `scrollTo` and `scrollToEnd` are imperative commands. `zoomScale` is reported in scroll events and applied to the reported metrics; the visible content scale remains 1 because Qt `Flickable` scaling is not wired. `contentContainerStyle` is handled transitively by the child `View`. |
| `TextInput`                | ⚠      | Renders through the QNX platform override: `defaultValue`/`value`, `onChange`, `onChangeText`, `onFocus`, `onBlur`, `onKeyPress`, `onSubmitEditing`, `onSelectionChange`, `placeholder`, `multiline`, `maxLength`, `editable`, `secureTextEntry`, font size, and colour all work; `focus`/`blur` commands reach the QML item. `mostRecentEventCount` is tracked for controlled edits. IME is not implemented because this QNX target has no software keyboard / input-method framework wired. |
| `Pressable`                | ✅     | Renders and `onPress` fires from a real pointer press; covered by a host test.                                                                                                                                                                                                                                                                                                                                                                                                             |
| `FlatList`                 | ✅     | Renders and virtualises: the window follows the scroll and off-window cells are released. `onLayout` and `onContentSizeChange` both reach it. Covered by a host test.                                                                                                                                                                                                                                                                                                                      |
| `VirtualizedList`          | ✅     | Covered transitively — `FlatList` is a thin wrapper over it, and the virtualisation asserted in that test is this component's.                                                                                                                                                                                                                                                                                                                                                             |
| `SectionList`              | ✅     | Renders through `VirtualizedSectionList` over `ScrollView` and `VirtualizedList`. Covered by a host test.                                                                                                                                                                                                                                                                                                                                                                                  |
| `VirtualizedSectionList`   | ❓     | Untested, same reasoning as `SectionList`.                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `Button`                   | ✅     | Mounts and reports presses. Opacity press animation reaches the mounted view through the connected `NativeAnimated` backend. `View`/`Text`/responder system are ready.                                                                                                                                                                                                                                                                                                                     |
| `TouchableOpacity`         | ✅     | Mounts through the responder system. Opacity animation now uses the connected `NativeAnimated` backend; responder system is exercised by `Pressable`.                                                                                                                                                                                                                                                                                                                                      |
| `TouchableHighlight`       | ❓     | Untested, same reasoning as `TouchableOpacity`.                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `TouchableWithoutFeedback` | ❓     | Untested, same reasoning as `TouchableOpacity`.                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `ImageBackground`          | ✅     | Composes `View` and `Image` with an explicit QNX platform override. The image is drawn behind the children, and `resizeMode` is passed through to `Image`. Covered by a host test.                                                                                                                                                                                                                                                                                                         |
| `KeyboardAvoidingView`     | ✅     | No-op on QNX: there is no software keyboard or `Keyboard` native module, so it renders its children in a `View` and ignores `behavior`, `keyboardVerticalOffset`, and `enabled`.                                                                                                                                                                                                                                                                                                           |
| `ActivityIndicator`        | ✅     | Registered, mounts, and renders as a Qt Quick circular spinner. `animating`, `color`, `hidesWhenStopped`, and `size` apply. Covered by a host test.                                                                                                                                                                                                                                                                                                                                        |
| `RefreshControl`           | ✅     | No-op on QNX: there is no native pull-to-refresh gesture, so it renders nothing. `refreshing` and `onRefresh` are accepted but ignored.                                                                                                                                                                                                                                                                                                                                                    |
| `Modal`                    | ✅     | `ModalHostView` renders as a full-screen overlay `View`. The inner `View` background and content are painted. `onShow`, `onRequestClose`, and `onDismiss` are not wired. Covered by a host test.                                                                                                                                                                                                                                                                                           |
| `SafeAreaView`             | ✅     | `SafeAreaViewComponentDescriptor` registered and mounts as a `View`. Insets are zero on QNX. Covered by a host test.                                                                                                                                                                                                                                                                                                                                                                       |
| `Switch`                   | ✅     | Renders and toggles as a QML switch; `value`, `disabled`, `onTintColor`, `thumbTintColor`, `tintColor`, and `onValueChange` all work. Covered by a host test.                                                                                                                                                                                                                                                                                                                              |
| `StatusBar`                | ✅     | No-op: QNX targets have no status bar to control. Exports the same static API as React Native's StatusBar, but calls do nothing.                                                                                                                                                                                                                                                                                                                                                           |

Android- and Apple-only exports are out of scope for this platform:
`DrawerLayoutAndroid`, `ProgressBarAndroid`, `TouchableNativeFeedback`, and
`InputAccessoryView`.

Counting the 22 components above: 7 work to some degree, 9 are untested
compositions over parts that already work, and 6 need native work.

## `View` props

| Prop                                                                                    | Status | Notes                                                                                                                                                                             |
| --------------------------------------------------------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Layout (Yoga: flex, padding, position…)                                                 | ✅     | Applied as absolute geometry; Yoga is the only layout authority.                                                                                                                  |
| `backgroundColor`                                                                       | ✅     | Packed to 0xAARRGGBB and set as `Rectangle.color`.                                                                                                                                |
| `opacity`                                                                               | ✅     | `QQuickItem::setOpacity`.                                                                                                                                                         |
| `borderRadius`                                                                          | ⚠      | Per-corner radii are rendered with a Qt Quick `Shape` rounded-rectangle path when they differ; uniform radii still use the fast `Rectangle`. Child clipping is rectangular, so content is not clipped to the rounded shape.              |
| `borderWidth`, `borderColor`                                                            | ⚠      | All four edges are read. When uniform they are represented faithfully by `Rectangle.border`; when non-uniform they collapse to the top edge.                                       |
| `transform`                                                                             | ⚠      | `translateX`/`translateY`, `scale`, and `rotateZ` are applied via `QQuickItem` position/scale/rotation. `transformOrigin`, `skew`, `perspective`, and arbitrary matrices are not. |
| `onLayout`                                                                              | ✅     | Emitted via `ViewEventEmitter` when the shadow node layout is applied.                                                                                                            |
| `onTouchStart`/`Move`/`End`                                                             | ⚠      | Single pointer via mouse and multi-pointer via `QTouchEvent`. Each active touch is captured to the view it started on (responder gestures override the target).                   |
| Responder props (`onStartShouldSetResponder`, `onResponderGrant`, `onResponderRelease`) | ✅     | React's responder negotiation runs on top of the touch events and is covered by a host test.                                                                                      |
| Accessibility props                                                                     | ⚠      | `accessible`, `accessibilityLabel`, `accessibilityRole`, `accessibilityHint`, `accessibilityValue`, and `accessibilityState` are forwarded as QML dynamic properties so they can be read by tests or a future bridge. Qt Quick's accessibility engine is not connected, so there is no screen reader output. |

## `Text`

| Aspect                     | Status | Notes                                                                                                     |
| -------------------------- | ------ | --------------------------------------------------------------------------------------------------------- |
| String content             | ✅     | Fragments flattened onto a Qt Quick `Text` item.                                                          |
| `fontSize`, `color`        | ✅     | Applied per fragment.                                                                                     |
| Mixed styling in one block | ✅     | Carried as Qt rich text, because Qt Quick's `Text` applies one font and colour to the whole item.         |
| Wrapping                   | ✅     | Measured with `QTextLayout` against the available width; the item is set to wrap so paint matches layout. |
| `numberOfLines`            | ✅     | Limits measured lines and sets Qt Quick `maximumLineCount`; `elide` is applied when the line limit is active. |
| Attachments (inline views) | ❌     | Not supported by Qt Quick `Text`; React Native's generic manager reports them as zero-sized, so no text/attachment layout is available. |
| Font family                | ✅     | Passed to Qt, with bundled font files (`*.ttf`, `*.otf`, `*.ttc`) auto-registered from `assets/fonts` and system font directories before falling back. |

## `Image`

| Aspect                                    | Status | Notes                                                                                                                      |
| ----------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------- |
| `data:` URIs                              | ✅     | Decoded by `QnxImageProvider` and served as `image://rnqnx/…`, because Qt Quick's `Image` cannot read data URIs.           |
| `file:` and `http(s):`                    | ⚠      | Passed straight to Qt, which fetches them. Untested here — the playground uses a data URI so it needs no network.          |
| Bundler assets (`require('./x.png')`)     | ✅     | Resolved through `Image.resolveAssetSource` and covered by a host test.                                                    |
| `defaultSource`                         | ✅     | Used as the image URI when no primary `source` is provided; covered by a host test.                                        |
| `loadingIndicatorSource`                | ✅     | Resolved like `source`/`defaultSource` and shown as an overlaid child `Image` while the primary source is loading; hidden on `Ready` or `Error`. Covered by a host test. |
| `onLoad`, `onError`, `onLoadEnd`          | ✅     | QML `Image.status` changes are bridged to `ImageEventEmitter`; covered by a host test.                                     |
| `http(s):` sources                       | ⚠     | Passed straight to Qt Quick's `Image`; not exercised by the existing host tests.                                           |
| `Image.getSize`, `prefetch`               | ✅     | `ImageLoader` TurboModule resolves `getSize` for `data:`, `file:`, `qrc:`, and absolute paths. `prefetch` is a no-op stub. |
| `resizeMode`                              | ✅     | Maps to QML `Image.fillMode`. Covered by a host test.                                                                      |

## Platform modules

| Module                                                  | Status | Notes                                                                   |
| ------------------------------------------------------- | ------ | ----------------------------------------------------------------------- |
| `Platform`                                              | ⚠      | `OS`, `select`, `Version`, and constants from the running system.       |
| `NativeMicrotasksCxx`, `NativeIdleCallbacksCxx`         | ✅     | React Native's own C++ modules, via `DefaultTurboModules`.              |
| `ExceptionsManager`                                     | ✅     | Reports to the host and logs; `dismissRedbox` is an honest no-op.       |
| `DeviceInfo`, `SourceCode`                              | ✅     | Real values: screen metrics from Qt, and the bundle the host evaluated. |
| `FileReaderModule`, `SegmentFetcher`, `WebSocketModule` | ✅     | Installed as honest no-op TurboModules so bundles that reference them do not crash on lookup. `FileReaderModule` and `SegmentFetcher` reject with an explanatory error; `WebSocketModule` operations are no-ops because there is no QNX socket backend wired yet. |
| `UIManager`                                             | n/a    | Not a TurboModule; bridgeless React Native serves it from JS.           |
