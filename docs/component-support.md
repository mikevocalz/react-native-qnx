# Component support

Each React Native component, with one column per target. The host column comes
from the Qt Quick renderer tests. The Pi 400 column covers the custom BCM2711
image: View, Text, TextInput and Pressable have scoped receipts there, the rest
are unverified. Stock Pi 4 QSTI has its own column because the Pi 400 image does
not establish QSTI support; nothing has run there yet. The
[evidence gallery](v1/evidence-gallery.md) lists every receipt by target.

| Status        | Column      | Meaning                                                          |
| ------------- | ----------- | ---------------------------------------------------------------- |
| `supported`   | Host        | The behavior in the notes works on the host. Not full RN parity. |
| `partial`     | Host        | Works with the limits listed in the notes.                       |
| `no-op`       | Host        | Accepts calls without doing the platform behavior.               |
| `unsupported` | Host        | Not implemented.                                                 |
| `scoped`      | Device      | Only the linked device scenario ran.                             |
| `failed`      | Device      | The linked device scenario ran and failed.                       |
| `unverified`  | Host/device | No claim either way.                                             |

The opt-in [v2 Qt APIs](v2/README.md) have their own
[validation receipt](v2/validation.md). `QtSvgDocument` has Linux host
React/Fabric rendering coverage; native motion and graphics expose C++ APIs.
QNX/Marathon device coverage and full `react-native-svg`, Reanimated, Worklets
and GPU-library compatibility remain separate gates. A pinned Dawn WebGPU
backend ran on the Pi 400 through OpenGL ES, in a native test app only
([WebGPU on QNX](v2/webgpu-qnx.md)); no React Native WebGPU, TypeGPU, Three.js
or Skia component is supported.

Edit [component-support.json](component-support.json), then run `pnpm docs:sync`.
Device evidence must name the board, image, revision and observed behavior.
View/Text's scoped result covers Hello World layout/paint and title rendering;
it does not promote every prop in the notes to device support.

Android- and Apple-only exports are out of scope: `DrawerLayoutAndroid`,
`ProgressBarAndroid`, `TouchableNativeFeedback`, and `InputAccessoryView`.

The v1 interaction scope is the existing Animated/native-driver, single-pointer
and Pressable path, subject to device validation. Reanimated, Worklets and RNGH
runtime integration remain [a separate gap](reanimated-gesture-handler-qnx-map.md).
IME-backed text input and multi-touch are open gates.

## `react-native-svg` elements (opt-in)

Built with `RNQNX_ENABLE_QT_RNSVG=ON`; these are not React Native core
components. Host status is the Linux fixture plus golden-pixel tests; device
status is the scoped Pi 400 gallery run in the
[validation receipt](v2/validation.md#react-native-svg). Details and the full gap
list are in [the guide](v2/react-native-svg.md).

| Element or prop                                                    | Host      | Pi 400 device | Notes                                                                                                                                                                                       |
| ------------------------------------------------------------------ | --------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Svg`                                                              | supported | scoped        | `viewBox` and `preserveAspectRatio`, background color, nested `<Svg>`, `onLayout`. No `toDataURL`, `getBBox`.                                                                               |
| `Path`, `Rect`, `Circle`, `Ellipse`, `Line`, `Polygon`, `Polyline` | supported | scoped        | Fill, stroke, dashes, caps, joins, miter limit, `vectorEffect`, fill rule, inheritance from `G`, markers on `Path` and `Line`.                                                              |
| `G`, `Defs`, `Use`, `Symbol`                                       | supported | scoped        | `Use` of a `Symbol` applies its `viewBox` to `width` and `height`; context paint.                                                                                                           |
| `LinearGradient`, `RadialGradient`, `Stop`                         | supported | scoped        | Both unit systems, `gradientTransform`, per-stop alpha, `spreadMethod` (through the overlay), focal point outside the circle.                                                               |
| `Pattern`, `Marker`                                                | supported | unverified    | Both unit systems, `viewBox`, `patternTransform`; `orient`, `markerUnits`, context paint.                                                                                                   |
| `ClipPath`, `Mask`                                                 | supported | scoped        | `clipRule` evenodd and nonzero (unset clips as evenodd, like the package's native views), text in a clip path, nested clip paths, luminance and alpha masks.                                |
| `Text`, `TSpan`, `TextPath`                                        | supported | scoped        | Per-character lists, chunk anchors, `textLength` (overlay), spacing, decorations, baselines, `inlineSize`, `textPath` align and stretch. No `direction`.                                    |
| `Image`                                                            | partial   | unverified    | `data:`, files, bundled assets and HTTP(S) through the host image loader; `onLoad`. Not SVG sources or uncached responses; see [the guide](v2/react-native-svg.md#limits-with-their-cause). |
| `Filter` and the 17 `Fe*` primitives                               | supported | unverified    | Ten primitives the package never sends come from the overlay. Golden images from resvg for each.                                                                                            |
| `ForeignObject`                                                    | partial   | unverified    | Live views in a clipped, transformed box; they draw above the painted texture.                                                                                                              |
| `onPress` and responder props on elements                          | supported | unverified    | Hit test follows fill, stroke, transforms, `clipPath`, `mask` and `pointerEvents`.                                                                                                          |
| Animated props                                                     | partial   | scoped        | JavaScript-driven updates repaint without remounting. No Reanimated or Worklets path.                                                                                                       |
| `SvgXml`, `SvgCss`, `SvgUri` and `parse`                           | supported | unverified    | Parsed into the same elements; the package's parser limits apply (see the guide).                                                                                                           |

## Qt native UI components (opt-in)

`RNQnxDrawer`, `RNQnxTabBar` and the `ExpoImage` view are Fabric components
this renderer adds, not React Native core components. They are built with
`RNQNX_ENABLE_QT_NATIVE_UI` (drawer and tab bar) and `RNQNX_ENABLE_QT_EXPO_IMAGE`
(the view `expo-image` renders), both on by default in a consumer app build and
off in every other build. Host status is the Qt Quick pointer and key test in
`tests/native/qt-native-ui` (Qt 6.12.0, offscreen, software renderer). Nothing
here has run on a Pi 400 yet.

| Component        | Host    | Pi 400     | Limits                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------- | ------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `RNQnxDrawer`    | partial | unverified | Two children: the panel, then the content. Yoga lays both out, so JavaScript styles both absolute at the container's left edge and the panel `drawerWidth` wide; native only moves them. A right-hand drawer is positioned by a transform. A drag that starts in the edge strip (`edgeWidth`, default 24 px) is not delivered to React views under it. Release velocity is read from Qt's pointer events; the tests cannot check it against real input, so the fling threshold (500 px/s) is untuned. |
| `RNQnxTabBar`    | partial | unverified | The `auto` layout compares `availableWidth`, or the parent view's width when it is 0, to `sideBreakpoint`; it does not compare its own width, because a rail would then switch back. Image icons are not tinted. The bar draws what its frame gives it; JavaScript sizes the frame from the size in `onLayoutMode`.                                                                                                                                                                                   |
| `ExpoImage` view | partial | unverified | See [`@rn-qnx/expo-image-qnx`](../packages/expo-image-qnx/README.md): `contentPosition` honors only the named edge, `transition` is always a cross-dissolve, tint and blur need `QtQuick.Effects` (absent from the Qt 6.12.0 host build used for the tests), request `headers`, blurhash, thumbhash and animated images are ignored.                                                                                                                                                                  |

Touch and hit testing: `QtTouchDispatcher` now orders siblings by `z` (stable,
so equal `z` keeps sibling order) when it looks for the view under a pointer.
The drawer needs it: the panel (`z` 2) must win over the content it overlaps,
and the scrim, the last child of the content, must win over the buttons under it.

## `View` props

| Prop                                                                                    | Status | Notes                                                                                                                                                                                                                                                                                                        |
| --------------------------------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Layout (Yoga: flex, padding, position…)                                                 | ✅     | Applied as absolute geometry; Yoga is the only layout authority.                                                                                                                                                                                                                                             |
| `backgroundColor`                                                                       | ✅     | Packed to 0xAARRGGBB and set as `Rectangle.color`.                                                                                                                                                                                                                                                           |
| `opacity`                                                                               | ✅     | `QQuickItem::setOpacity`.                                                                                                                                                                                                                                                                                    |
| `borderRadius`                                                                          | ⚠      | Per-corner radii are rendered with a Qt Quick `Shape` rounded-rectangle path when they differ; uniform radii still use the fast `Rectangle`. Child clipping is rectangular, so content is not clipped to the rounded shape.                                                                                  |
| `borderWidth`, `borderColor`                                                            | ⚠      | All four edges are read. When uniform they are represented faithfully by `Rectangle.border`; when non-uniform they collapse to the top edge.                                                                                                                                                                 |
| `transform`                                                                             | ⚠      | `translateX`/`translateY`, `scale`, and `rotateZ` are applied via `QQuickItem` position/scale/rotation. `transformOrigin`, `skew`, `perspective`, and arbitrary matrices are not.                                                                                                                            |
| `onLayout`                                                                              | ✅     | Emitted via `ViewEventEmitter` when the shadow node layout is applied.                                                                                                                                                                                                                                       |
| `onTouchStart`/`Move`/`End`                                                             | ⚠      | Single pointer via mouse and multi-pointer via `QTouchEvent`. Each active touch is captured to the view it started on (responder gestures override the target).                                                                                                                                              |
| Responder props (`onStartShouldSetResponder`, `onResponderGrant`, `onResponderRelease`) | ✅     | React's responder negotiation runs on top of the touch events and is covered by a host test.                                                                                                                                                                                                                 |
| Accessibility props                                                                     | ⚠      | `accessible`, `accessibilityLabel`, `accessibilityRole`, `accessibilityHint`, `accessibilityValue`, and `accessibilityState` are forwarded as QML dynamic properties so they can be read by tests or a future bridge. Qt Quick's accessibility engine is not connected, so there is no screen reader output. |

With `RNQNX_ENABLE_INPUT_LIFECYCLE=ON` (default OFF), the dispatcher additionally
handles touch cancellation, window deactivation, mouse-grab loss and target
removal, and updates terminal coordinates and RN 0.88 high-resolution timestamps.
This is an input prerequisite, not Reanimated or Gesture Handler support. See
[the source audit and validation instructions](reanimated-qnx-source-audit.md).
The [validation receipt](validation/qt-input-lifecycle-2026-11-07.md) records host
ON/OFF tests and synthetic Qt input on physical QNX. The later
[JS-delivery proof](evidence/pi400-input-js-2026-11-07.md) checks raw Fabric
JavaScript callbacks. USB/touch hardware, React component interaction and
Marathon/Wayland remain unverified.

## `Text`

| Aspect                     | Status | Notes                                                                                                                                                  |
| -------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| String content             | ✅     | Fragments flattened onto a Qt Quick `Text` item.                                                                                                       |
| `fontSize`, `color`        | ✅     | Applied per fragment.                                                                                                                                  |
| Mixed styling in one block | ✅     | Carried as Qt rich text, because Qt Quick's `Text` applies one font and colour to the whole item.                                                      |
| Wrapping                   | ✅     | Measured with `QTextLayout` against the available width; the item is set to wrap so paint matches layout.                                              |
| `numberOfLines`            | ✅     | Limits measured lines and sets Qt Quick `maximumLineCount`; `elide` is applied when the line limit is active.                                          |
| Attachments (inline views) | ❌     | Not supported by Qt Quick `Text`; React Native's generic manager reports them as zero-sized, so no text/attachment layout is available.                |
| Font family                | ✅     | Passed to Qt, with bundled font files (`*.ttf`, `*.otf`, `*.ttc`) auto-registered from `assets/fonts` and system font directories before falling back. |
