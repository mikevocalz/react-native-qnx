# Handoff, 2026-11-13: run and control the app on the Pi 400

Read this first if you are the next person or model picking up the QNX work.
It says what exists, how to load the app on the Pi 400 and drive it, what
state everything is in, and what is still open. Facts here were checked on
the board and on GitHub on 2026-11-13. `main` was at `eda99b9` (PR #160).

Release gates in [v1-readiness.json](../releases/v1-readiness.json) are all
still `pending`. Nothing in this handoff changes a gate. Device results below
come from one Pi 400 with a custom BCM2711 image, not from a stock Pi 4 QSTI
board.

## Owner rules that apply to every session

These came from the repository owner during this work. Follow them.

1. **No gaps.** Fix the root cause. Call something unsupported only with
   evidence that the platform cannot do it, and then build the closest
   working thing. A limits list in a PR body is unfinished work.
2. **One window per app, ever.** Never start a second copy of an app on the
   Pi. Dev and release builds of one app share one instance key. Close any
   test window you opened.
3. **No Hello World.** Never show, deploy or launch it on the Pi.
4. **The Pi boots to the QNX desktop.** Never add an app autostart or a boot
   hook that starts an app. The window manager swap below is the only boot
   change, and it keeps the stock desktop as a fallback.
5. **Never reboot with software.** `shutdown -S reboot` and `shutdown -b`
   both halt this board until power is cut. Ask the owner to unplug and
   replug it.
6. **Mouse and keyboard must work.** Check `/dev/io-hid/io-hid` exists before
   and after any Pi work.
7. **Polish counts.** The app on the owner's tile must be the current build,
   with the window header and no black screens.
8. **Every app gets a generated icon set.** `prepare-native` builds the
   identity tool when missing. `--skip-identity-tool` no longer exists.
9. **Plain prose in docs and PR bodies.** Use the `no-ai-slop` rules: no
   binary contrasts, no puffery, no throat-clearing, no decorative em dashes.
10. **Caches may be cleared without asking.** The Mac disk is small. Some
    deletes are blocked for agents, so ask the owner to run them.

Process rules learned the hard way:

- Never use `pkill` or `killall` on the build container or the Pi. Signal
  only PIDs you started, with a plain `kill`. Never `kill -9` an app: it
  froze the desktop once.
- The build container has 6 cores shared by all agents. Use
  `ninja -j 2` or `cmake --build ... --parallel 2`, never `build.sh` as is.
- A subagent that ends its turn while CI or a build runs does not come back
  on its own. Block on `gh pr checks <n> --watch` or a log loop instead.
- Merge with `gh pr merge --merge`. Force-push is blocked. The `main`
  ruleset (id 27120426) requires a pull request and these checks:
  `validate`, `image-cache`, and both `Qt 6.11 / RN 0.88 / Hermes` legs.
  `Devin Review` is a third-party bot and is not required.
- Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`
  (older commits carry Opus 5.5). PR bodies end with
  `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- Do not create worktrees. Clone throwaway repos, push, then delete the clone
  with an absolute `rm -rf`. Never touch the owner's `~/react-native-qnx`.

## Connect to the Pi

The Pi is `192.168.2.2` on the Mac's USB Ethernet link. The Mac is
`192.168.2.1` and shares its internet. User `qnxuser`, passwordless `sudo -n`.

```sh
K=~/qnx-pi400-8.0.5/pr102-ssh
ssh -i $K/id_ed25519 -o UserKnownHostsFile=$K/pr104-sdk-trusted-hosts \
    -o BatchMode=yes qnxuser@192.168.2.2
```

`pidin` run as `qnxuser` prints permission errors for other users'
processes. Run `sudo -n pidin -F "%a %N %A"` to see everything.

### See the screen

```sh
# on the Pi: capture the display, then copy it to the Mac
sudo -n screenshot -file=/tmp/now.bmp && sudo -n chmod 644 /tmp/now.bmp
# on the Mac
scp -i $K/id_ed25519 -o UserKnownHostsFile=$K/pr104-sdk-trusted-hosts \
    qnxuser@192.168.2.2:/tmp/now.bmp . && sips -s format png -Z 1280 now.bmp --out now.png
```

The stock `screenshot` tool captures the composited display. Every app also
has `--screenshot <png>` (renders, saves and exits) and
`--window-size WxH`. The in-app capture reads the Qt window, not the screen.
A black capture with a running desktop means the window manager is stuck:
see "Desktop recovery".

### Drive the mouse and keyboard

Pointer events must come through Screen with a real pointer device. The
injector is [tools/qnx-input/rnqnx-inject.c](../../tools/qnx-input/rnqnx-inject.c)
(built by `tools/qnx-input/build.sh`; copies live in
`/data/home/qnxuser/bin/rnqnx-inject*`, use the newest). It creates its own
pointer and keyboard devices and sets the position flag and a millisecond
timestamp. Without those, Screen puts the pointer at 0,0 and every click pair
reads as a double click.

Commands: `move`, `down`, `up`, `click`, `dclick`, `drag`, `wheel`, `hwheel`,
`mods`, `key`, `keydown`, `keyup`, `type`, `sleep`. Alt+Tab needs modifier
mask `4`. Useful key codes: F1 `f0be`, Down `f054`, Enter `f00d`, Escape
`f01b`. Take a screenshot after a short settle: the capture can lag one
input event.

`pnpm pi:mouse-smoke` (script `scripts/pi-mouse-smoke.sh`) checks title-bar
drag, right-edge resize and double-click maximise and restore. On a freshly
started app set `RNQNX_MOUSE_FRAME=WxH+X+Y` and keep the window restored.
Details are in [pi400-desktop-app.md](../getting-started/pi400-desktop-app.md).

### Start, restore and stop the app

The owner's tile app is `org.rnqnx.showcase`, the component gallery
(`apps/component-gallery`). Always launch it through its guard script:

```sh
/data/home/qnxuser/run-chrome-app.sh        # execs rnqnx-tile-1/run-app.sh
```

`run-app.sh` (source: `template/qnx/run-app.sh`) checks `pidin` first. Flags:
`--replace` (ask the running copy to quit, wait, then SIGTERM its pid, then
start), `--restore-only`, `--stop-running`. The app listens on
`/tmp/rnqnx-<base app id>`; commands are `restore`, `info` and `quit`, each
answered `ok pid=<n> kind=<dev|release>`. A second launch brings the first
window forward and exits. Stop an app with a plain `kill <pid>`. The process
name shows as `org.rnqnx.showcase`.

The desktop tile "QNX Components" is installed in
`/system/etc/desktop_files/org.rnqnx.showcase.desktop` (backups end in
`.before-rnqnx-tile` and `.before-run-app`). `demolauncher` reads tiles only
when it starts.

### Pending owner action: swap the window manager

PR #160 merged `swap-winmgr.sh`. The binary is staged at
`/data/home/qnxuser/rnqnx-wm/rnqnx-winmgr` but the board still ran the
previous manager when this was written. Permission checks stop agents from
restarting the manager, so the owner runs:

```sh
ssh -i $K/id_ed25519 -o UserKnownHostsFile=$K/pr104-sdk-trusted-hosts -o BatchMode=yes \
  qnxuser@192.168.2.2 'sudo -n sh /data/home/qnxuser/rnqnx-wm/swap-winmgr.sh'
```

It backs up the old binary once, installs atomically, stops the old manager
with SIGTERM, starts the new one, restarts `demolauncher`, relaunches the
tile app through `run-chrome-app.sh --replace`, checks the result, and rolls
back by itself if the new manager exits within 5 seconds. `--check` prints
the plan, `--undo` restores the backup. After the swap, run the two-window
proof: two windows with one app key show one dock entry, the duplicate is
minimised and the first raised, and `/tmp/rnqnx-winmgr.log` says
`second window of '<key>'`. The proof needs the `org.rnqnx.proofapp` copies,
not the owner's app.

### Desktop recovery

If the screen is black while `screen`, `drm-rpi4`, the window manager and the
launcher are all alive, the manager and launcher are stuck waiting on the
display server. Restart them:

```sh
sudo -n slay demolauncher rnqnx-winmgr
sudo -n sh -c 'on -d /data/rnqnx-winmgr/rnqnx-winmgr -s demolauncher,st,gtk; sleep 2; on -d demolauncher -a /system/etc/desktop_files'
```

The watcher in `rnqnx-desktop.sh` starts the stock manager when ours stops,
so stop that first if you want a clean restart.

### Audio

`io-snd` is not started at boot. An agent started it by hand with
`sudo io-snd -c /etc/system/config/sound/io_snd.conf`. The only configured
output is the 3.5 mm headphone jack (`bcm2711_pwm`). A USB audio device also
works if attached. The image has no HDMI audio driver, so sound never comes
out of the monitor. Starting `io-snd` at boot is a boot-script change and is
not done: stage an installer and give the owner a one-line command, as with
the window manager.

## Build and deploy

All QNX cross-builds run in the colima VM, docker container `qnx805-build`
(QNX SDP 8.0.5, aarch64). Run commands with
`colima ssh -- docker exec qnx805-build sh -c '...'`. The VM has 6 cores,

`scripts/qt-public/` ([README](../../scripts/qt-public/README.md)), which
now fails unless the Release flags contain `-O2`.

Deploy to a new folder under `/data/home/qnxuser/`, run the app once with
`--screenshot`, look at the PNG, then point `run-chrome-app.sh` at it with a
rollback copy. The standard rollback files are
`run-chrome-app.sh.before-tile1`, `run-chrome-app-pre-router.sh`.

The Mac has little free disk. After large deletes in the VM run
`colima ssh -- sudo fstrim -av` to give the space back. Caches
(`~/.npm/_cacache`, `~/Library/Caches/pnpm`) are safe to remove. Use
`npx -y pnpm@12.18.0` because the Homebrew pnpm cannot switch versions.

## Known gaps and what they need

- **Media.** `react-native-video` 7.0.0-beta.12 does not load on the pinned
  Nitro v1 (`createHybridObject` is missing and its 88-method contract is
  larger than what exists). A JavaScript subset of `useVideoPlayer` and
  `VideoView` exists but is not aliased in Metro. `react-native-audio-api`
  has no QNX player or JSI installer. FFmpeg has no TLS, so `https://`
  streams need Qt Network. Audio plays through the jack only.
- **WebGPU.** Dawn runs on the OpenGL ES backend only. The Vulkan driver
  reports 1.0, Dawn needs 1.1, and the ICD file names a library that does not
  exist. Device loss is injected, not real. Nothing is timed. Skia Graphite,
  RN WebGPU, TypeGPU and Three.js are not started (`docs/v2/webgpu-qnx.md`
  has the pinned Dawn commit `1716e88c` and the mismatches).
- **Nitro.** A module in `nitroModules` calls `add_subdirectory` from a
  deferred call, which CMake rejects (noted in #147).
- **Native tests.** Six JS test files cannot run on a Mac (Linux or SDP
  tooling needed); CI is their first run.
