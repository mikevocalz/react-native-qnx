# Pi 400 device receipts, 2026-11-24

Labels: **Pi 400** is the board at `qnxuser@192.168.2.2` (QNX 8.0.0 `RaspberryPi400 aarch64le`), the board for every gate per
[ADR-0023](../../adr/0023-pi400-stands-in-for-device-parity.md). **container** is the Linux x86_64 container `qt-v1g`
(`ubuntu:24.04`, QNX SDP 8.0.5 `q++` 12.2.0, 6 CPUs). **host** is the Mac (macOS, Qt 6.12.0 from Homebrew, offscreen QPA).
Source: branch `gates/v1-closeout` on `main` `17e33d37` (the commit of each binary is in the pull request). Nothing here ran
on a stock Pi 4 QSTI. Every app was started by hand over ssh and stopped after its test; `drm-rpi4`, `screen`,
`/system/etc/startup` and the boot sequence were not touched and the board was not rebooted.

## Why clicks did not reach page content on 2026-11-23

[The previous receipt](../pi400-v1-gates-2026-11-23/README.md) built the playground without
`-DRNQNX_ENABLE_INPUT_LIFECYCLE=ON`. Without it the host never sets `__RNQNX_INPUT_LIFECYCLE__`, so title bar clicks (native Qt Quick)
worked and presses on React views never reached `Pressable`. `rnqnx-inject` was correct. Every build below sets the option, and
a click on the `Block JS` button logged `js-block-start` on the first try ([board/chrome-probe-macos-minimize-restore.txt](board/chrome-probe-macos-minimize-restore.txt)).

## Device parity (`device-parity`)

`apps/rn-playground/component-device-probe.js` ran on the Pi 400 with clicks, drags and wheel notches from `rnqnx-inject`
([board/component-probe.txt](board/component-probe.txt)). The 12 components that were `unverified` now have a `scoped` Pi 400
disposition with tested limits in `docs/component-support.json`: VirtualizedList, SectionList, VirtualizedSectionList, Button,
TouchableOpacity, TouchableHighlight, TouchableWithoutFeedback, ImageBackground, KeyboardAvoidingView, RefreshControl,
SafeAreaView, StatusBar. Findings worth knowing: `Button` without a `color` draws black text on this target; `RefreshControl`
fires no `onRefresh`; `TouchableOpacity` `onLongPress` fired 525 ms after `onPressIn`.

**Not met:** touch and a physical keyboard. No touch device is attached, and every key and pointer event came from the
injector through Screen. The gate asks to prove keyboard and touch.

Every run had `droppedFrames` 0 and `renderBackend` `opengl`. Hermes ran as an interpreter (`HERMESVM_ALLOW_JIT=0`). Startup is
about 250 ms slower than the 2026-11-23 numbers because this binary carries the title bar, the Nitro windows API and AppState.
Drawer drag uses `--timing-observe-ms`: the probe posts nothing, records when pointer events first and last reach the window, and
the frame window is those two instants (about 3 s, 100 moves of 30 ms from `rnqnx-inject drag 195 403 620 403 100`; the drawer
opened: [frames/drawer-physical-open.png](frames/drawer-physical-open.png)). Posting the drag as Qt mouse events
(`--timing-drag-steps`) did not move the drawer on the board (9 swaps, none during the drag, [perf/drawer-drag-posted-no-motion](perf/drawer-drag-posted-no-motion)),
so those runs are not used. Refresh rate: Screen reports `mode=1280x720@60` ([board/display-mode.txt](board/display-mode.txt),
`tools/qnx-input/rnqnx-display-mode.c`, a read-only Screen query). HDMI output is black here, so the display was not observed and a
swap is the end of a scene-graph swap, not a presented frame. The `drm_*` tools could not open the card without its module name and were not forced.

**Not met:** `docs/releases/performance-budgets.json` still has `unmeasured` Pi 400 fields and a `blocked` drawer-drag host lane.
Writing the numbers is a budget change that needs an ADR and the owner, so I did not make it. Frame intervals are swap intervals,
not presentation times.
