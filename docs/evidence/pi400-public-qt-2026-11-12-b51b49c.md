# Public-source Qt 6.12.0 on the Pi 400, November 12, 2026

Qt 6.12.0 was rebuilt for QNX aarch64le from the public `download.qt.io`
archive, with the evaluation build's module subset and configure options. Its
runtime was installed on the physical Pi 400 beside the evaluation runtime.
Hello World, the Qt/Nitro dispatcher probe and the Pressable probe all ran
with only the public-source Qt libraries and plugins loaded. The QNX loader's
own trace (`DL_DEBUG=libs`) records every object each run loaded.

Repository base: `b51b49cd8683e6e7d4b157ac3b82aea3d99ae97c` (main). No
repository source changed for this run; the application binaries are the
earlier device artifacts listed below.

## Build

Host tools and the QNX target were built from that tree inside the existing
`qnx805-build` container (QNX SDP 8.0.5, `qcc -Vgcc_ntoaarch64le`, GCC 12.2.0).
Recipes are in [`scripts/qt-public/`](../../scripts/qt-public/), with the
container layout in its [README](../../scripts/qt-public/README.md). The build
ran from copies with fixed `/work` and `/home/qnxbuild` paths. After review the
committed scripts take those paths from `layout.sh`; a configure-only run of
the committed `configure-qnx.sh` into a scratch directory produced the same
468 `FEATURE_*` cache values and the same `qglobal.cpp` compile line as the
real build (build-directory prefix aside). That check did not rebuild.

- Host tools: `[1754/1754]`, `EXIT=0 2026-11-12T05:16:05Z`.
- QNX target: `[1721/1721]`, `EXIT=0 2026-11-12T06:41:18Z`.

QNX configure line ([configure-qnx.sh](../../scripts/qt-public/configure-qnx.sh)):

```sh
configure -developer-build -release -optimize-size -no-pch -nomake tests -nomake examples \
  -prefix /data/qt612-public -extprefix /home/qnxbuild/qt-6.12.0-public/qnx-stage \
  -opengl es2 -qt-host-path "$host" -submodules qtbase,qtshadertools,qtdeclarative -- \
  -DCMAKE_TOOLCHAIN_FILE=.../qt612-public-qnx-aarch64le.cmake \
  -DCMAKE_SYSTEM_VERSION=800 -DFEATURE_no_prefix=OFF \
  -DFEATURE_widgets=OFF -DFEATURE_printsupport=OFF -DFEATURE_sql=OFF \
  -DFEATURE_dbus=OFF -DFEATURE_icu=OFF -DFEATURE_fontconfig=OFF \
  -DFEATURE_system_freetype=OFF -DFEATURE_system_harfbuzz=OFF \
  -DFEATURE_system_zlib=OFF -DFEATURE_system_png=OFF -DFEATURE_system_jpeg=OFF \
  -DFEATURE_system_pcre2=OFF -DFEATURE_vulkan=OFF -DFEATURE_qml_debug=OFF \
```

These options and targets match the evaluation's `configure-qt-qnx.sh`. The
differences are the public source path, host tools built from the same public
tree, `-no-pch` to bound disk use, and separate prefixes.

## License check

[`spdx-audit.py`](../../scripts/qt-public/spdx-audit.py) lists every file the
compiler read for the 16 runtime targets, from the dependency records ninja
stored during the build (`ninja -t deps` for all 1335 objects), so headers and
`#include`d `.c`/`.cpp` files count as well as the 1335 translation units. Of
the 6771 files read:

- 2680 files in the Qt module trees. 2667 carry
  `LicenseRef-Qt-Commercial OR LGPL-3.0-only OR GPL-2.0-only OR GPL-3.0-only`.
  The other 13 are bundled code kept beside Qt sources and named in a local
  `qt_attribution.json`: Unicode UCD and CLDR data (Unicode-3.0, 8 files),
  `tl::expected` (CC0-1.0), Khronos `qopengles2ext.h` (MIT), the Adobe Glyph
  List (BSD-3-Clause), FreeType's `qgrayraster.c` (`FTL OR GPL-2.0-only`, FTL
  taken) and the Imlib2-derived `qimagescale.cpp` (`BSD-2-Clause AND Imlib2`).
- 1016 files in 20 `3rdparty` components, each reported with every license its
  `qt_attribution.json` names. Some reach the build only through `#include`
  from an LGPL-headed Qt file, which the first audit missed: SHA-1, MD4, MD5,
  SHA-3, RFC 6234 and BLAKE2 through `qcryptographichash.cpp`, Robert Penner's
  easing equations through `qeasingcurve.cpp`, SipHash through `qhash.cpp`,
  forkfd through `forkfd_qt.c`, emoji-segmenter (Apache-2.0) through
  `qtextengine.cpp`, TinyCBOR and PCRE2's SLJIT.
- Qt-file attributions also name code inside LGPL-headed files: the X Server
  region helper in `qregion.cpp` (X11 AND HPND) and XSVG arc code in
  `qguisvg.cpp` (HPND-sell-variant).
- 2059 generated files in the build tree (module include headers, moc and
  registration output) were counted, not read; 1016 toolchain and QNX sysroot
  headers were counted only.

The 20 components: BLAKE2 (`CC0-1.0 OR Apache-2.0`), double-conversion,
Penner easing, libpsl and RFC 6234 (BSD-3-Clause), emoji-segmenter
(Apache-2.0), forkfd, HarfBuzz, MD4C and TinyCBOR (MIT), FreeType
(`FTL OR GPL-2.0-only`, plus its Zlib, MIT and MIT-open-group parts), libpng
(Libpng AND libpng-2.0), MD4, MD5 and SipHash (CC0-1.0), PCRE2 (BSD with
binary-package exception; SLJIT BSD-2-Clause), SHA-1 (public domain), SHA-3
(BSD-2-Clause and CC0-1.0), zlib (Zlib), JavaScriptCore masm (BSD-2-Clause),
and the Public Suffix List data in libpsl (MPL-2.0).

No file the compiler read is offered only under the GPL, and every Qt module
in the closure offers LGPL-3.0-only. QtShaderTools is used only as a host
build tool (`qsb`); none of its code is in the target closure.

Several components ship no license file of their own (emoji-segmenter, MD4,
MD5, SipHash, SHA-1, the Unicode data). The staging script now writes
`licenses/THIRD_PARTY_ATTRIBUTIONS.txt` from the audit (35 entries: name,
version, source path, SPDX id, copyright line and the license text to read),
copies the license files those attributions name (for example
`LICENSE.XSVG.txt`), and relies on each module's `LICENSES/<id>.txt` for the
text, such as `Apache-2.0.txt` for emoji-segmenter. Audit output SHA-256
`2bd001cdd4330a5a47ea40fb516f59eb9d98b5ab63ec6e7d4b194027c48faedb`;
attributions file `173830acff115ef792ed1ed4941f0a42e238b858abf2882ba020a3bd3e76261d`.

## Failure found on the way

The first Hello World attempt exited 134 with
`QQnxIntegration: failed to initialize EGL display, err=12289`
(`EGL_NOT_INITIALIZED`). The same launcher pointed at the evaluation runtime
failed identically, so the Qt build was not the cause. `/dev/drm/card0` and
`/dev/drm/renderD128` were `root:root 0660` with no entry for `qnxuser`, and
Mesa could not open them. The Screen/DRM startup changed on 2026-11-11 to boot
the stock desktop, and that path grants no GPU node access to `qnxuser`.

For these runs a temporary ACL was added with
`sudo setfacl -m u:qnxuser:rw` on both nodes and removed with
`setfacl -x u:qnxuser` afterwards; `getfacl` output before and after is
identical. Nothing under `/system/etc/startup` changed, no autostart marker or
boot hook was created, and the board was not rebooted. No proof process was
left running; the desktop's `fullscreen-winmgr` and `demolauncher` stayed up.
How a non-root app should get GPU access on this image was open at the time
of this run. The boot-script fix is now documented under
[GPU node access](../getting-started/raspberry-pi-400.md#gpu-node-access).

## Limits

- The application binaries were not rebuilt against the public Qt build; see
  above. A fresh RN/Qt link is the next step for a release candidate.
- The Release configuration has no `-O` level: `CMAKE_CXX_FLAGS_RELEASE` is
  `-DNDEBUG -DNDEBUG` in both the public and the evaluation build caches, and
  the QNX headers warn that `_FORTIFY_SOURCE` falls back to 0. The public
  build keeps that to stay identical; fixing it is a separate change. That
  change is [ADR-0017](../adr/0017-qt-qnx-optimization-level.md), and the
  rebuilt runtime is in
  [the -O2 receipt](pi400-public-qt-o2-2026-11-12-a79e16a.md).
- `-prefix` is `/data/qt612-public`; the board copy lives in the user's home
  and finds plugins and QML through environment variables.
- The three application executables carry
  `DT_RPATH=/home/qnxbuild/qt612-qnx/qtbase/lib:/home/qnxbuild/rn-build/hermes/lib`.
  QNX's loader searches `DT_RPATH` before `LD_LIBRARY_PATH` (the trace shows
  it trying those paths first). The runs above select the public libraries
  only because those build-host paths do not exist on the board. A shipped
  application must not carry a build-host RPATH; see
  [packaging](../packaging.md).
- No timing, memory or frame-pacing figures were measured.
- Pi 400 only; no stock Pi 4 QSTI, QNX VM or Marathon run.
- Local raw logs and readback copies:
  `~/qnx-pi400-8.0.5/qt-6.12.0-public/logs/` and
  `~/qnx-pi400-8.0.5/qt-6.12.0-public/device-2026-11-12/`. They are not
  committed. No QNX SDK file, Qt binary, evaluation artifact or credential is
  in this repository.
