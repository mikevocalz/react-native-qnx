# Public-source Qt 6.12.0 at -O2 on the Pi 400, November 12, 2026

The public-source Qt 6.12.0 runtime for QNX aarch64le was rebuilt at `-O2`
([ADR-0017](../adr/0017-qt-qnx-optimization-level.md)) with both QNX platform
plugin patches from [`scripts/qt-public/patches/`](../../scripts/qt-public/patches/).
It replaces the `-O0` runtime from
[the first public-source receipt](pi400-public-qt-2026-11-12-b51b49c.md) as the
runtime the component gallery app (`org.rnqnx.showcase`) uses on the physical
Pi 400. The app no longer loads the separately built plugin from
`/data/home/qnxuser/glfix`.

Repository base: `a79e16a` (main). Every file hash and the app ABI check are in
[qt-public-runtime-closure-o2-2026-11-12-a79e16a.json](qt-public-runtime-closure-o2-2026-11-12-a79e16a.json).

## Source

Same archive and security diffs as the first receipt: SHA-256
`98ff4f44bac6ec3e1e62ee2a4316ae0e3d15badb015d753cc0268a20db52f165`, with
`CVE-2026-116337` 0001 and 0002 and `CVE-2026-105924` applied to qtbase
`src/`. The extracted tree sits under `/work`, which is a git repository, so
the earlier `git apply` could have skipped every hunk and still exited 0. It
did not: `git apply --reverse --check` succeeds for all three diffs in that
tree, and the 0001 hunk (`MAX_REASON_PHRASE_SIZE + 64`) is present in
`qhttpnetworkreply.cpp`.

`apply-qnx-patches.sh` from `a79e16a` then applied
`qtbase-qnx-offscreen-surface.patch` and `qtbase-qnx-resize-swap.patch`
cleanly (8 files under `src/plugins/platforms/qnx`).

## Build

The existing tree `/home/qnxbuild/qt-6.12.0-public/qnx-build` in the
`qnx805-build` container was reconfigured in place: its `CMakeCache.txt` was
moved aside, then `configure-qnx.sh` from `a79e16a` ran under `guarded-run.sh`
with `MIN_KB=4194304 JOBS=5`. The host-tools build was not touched.

| Check                                       | Result                                                         |
| ------------------------------------------- | -------------------------------------------------------------- |
| `CMAKE_C_FLAGS_RELEASE`                     | `-DNDEBUG   -DNDEBUG -O2`                                      |
| `CMAKE_CXX_FLAGS_RELEASE`                   | `-DNDEBUG   -DNDEBUG -O2`                                      |
| `FEATURE_optimize_size` / `_full`           | `OFF` / `OFF`                                                  |
| `FLAGS` lines in `build.ninja`              | 2992: 2345 with `-O2`, 647 with `-O3`, 0 without an `-O` level |
| Build log end                               | `[1710/1710]`, `EXIT=0 2026-11-12T19:54:27Z`                   |
| `_FORTIFY_SOURCE` warnings in the build log | 0 (the `-O0` build log has 2248)                               |

The 647 `-O3` lines are QtCore and QtGui sources.
`qtbase/src/corelib/CMakeLists.txt` and `qtbase/src/gui/CMakeLists.txt` call
`qt_internal_add_optimize_full_flags()`, which compiles those two modules with
`-O3` whenever `optimize_size` is off. That is upstream Qt behaviour; the
`-optimize-size` build suppressed it. No compile line lacks an `-O` level.

The runtime has the same 159 files and 20 symlinks as the `-O0` runtime. The
16 ELF files changed and shrank from 122,755,752 to 51,271,416 bytes in total
(`libQt6Core` 25.2 MB to 12.8 MB, `libQt6Gui` 31.1 MB to 12.1 MB); the tarball
went from 30 MB to 18.4 MB. Every license, `qmldir` and `qmltypes` file is
byte-identical. `DT_NEEDED` closure is unchanged.

The license audit read 6788 files (6771 before) and found the same license
expressions, components and attributions. The extra files are one more
`include/QtGui` header and 16 more toolchain or sysroot headers (1016 to 1032). `libqqnx.so`
carries `QQnxIntegration::createPlatformOffscreenSurface`, which the stock
plugin lacks.

## Application ABI

The board's `org.rnqnx.showcase` (SHA-256
`7c1e726e0edd8545392f608ce4a793447c599e5f1770d2908abbf2f44155f57e`, the same
file as `/home/qnxbuild/wm-pr/qnx-build/consumer/qnx/org.rnqnx.showcase/`)
imports 423 versioned Qt symbols. All 423 are defined by the new libraries, as
they were by the old ones. The `-O2` libraries export 1232 fewer symbols than
the `-O0` ones (inline and template functions the compiler no longer emits out
of line); the app uses none of them. The app was not rebuilt. Its `DT_RPATH`
names build-host paths that do not exist on the board, so `LD_LIBRARY_PATH`
selects the runtime, as in the first receipt.

## Device run

The tarball was copied to the board and unpacked into the new directory
`/data/home/qnxuser/qt612-public-o2`; `sha256sum -c SHA256SUMS` reported 159
of 159 OK. `/data/home/qnxuser/qt612-public` was left as it was.

A copy of `run-chrome-app.sh` was pointed at the new runtime:
`Q=/data/home/qnxuser/qt612-public-o2`, and `QT_QPA_PLATFORM_PLUGIN_PATH` and
`QT_PLUGIN_PATH` set to `$Q/plugins/platforms` and `$Q/plugins` instead of the
`glfix` tree. With `rnqnx-winmgr` and `demolauncher` running, three
`--screenshot` runs of that copy each wrote a 1280x800 frame
(`RNQNX_PLAYGROUND_SCREENSHOT`) showing the component gallery with its title
bar, not a black window. The copy then replaced `run-chrome-app.sh`; the
previous script is kept as `run-chrome-app.sh.before-o2`. The running app was
stopped with a plain `kill` and relaunched from the new script. `pidin mem`
for the new process lists `libQt6Core.so.6.12.0` at 10 MB and
`libQt6Gui.so.6.12.0` at 9 MB, the sizes of the `-O2` files, and a display
capture with `screenshot` showed the gallery window on the desktop under
`rnqnx-winmgr`.

### Launch-to-screenshot time

Wall time from starting the launcher to the process exiting after
`--screenshot`, measured with bash `time` on the board while the app's own
instance was running. This covers Qt and Hermes start-up, the React render,
`grabWindow()`, PNG encoding and teardown. It is a proxy for
startup-to-first-frame, not a presented-frame timestamp.

| Launcher                              | Runs (s)                                 | Median |
| ------------------------------------- | ---------------------------------------- | ------ |
| `-O0` runtime with the `glfix` plugin | 3.383, 3.384, 3.387, 3.302, 3.051, 3.113 | 3.34 s |
| `-O2` runtime                         | 1.904, 1.521, 1.425, 2.132, 2.031, 2.099 | 1.97 s |

Runs 4 to 6 alternated the two launchers.

## Limits

- The first receipt's hello world, Qt/Nitro dispatcher and Pressable runs were
  not repeated on this runtime; only the component gallery ran. No release
  gate changed.
- Six samples per launcher, one board, one app. Frame pacing and RSS were not
  measured.
- `-prefix` is still `/data/qt612-public`; the board copy finds plugins and
  QML through environment variables.
- Local logs and runtime: `~/qnx-pi400-8.0.5/qt-6.12.0-public/logs/qnx-build-o2.log`,
  `runtime-o2/`, `runtime-o2-spdx-audit.json` and
  `qt612-public-runtime-o2.tar.gz`. They are not committed. No QNX SDK file
  or Qt binary is in this repository.
