# Physical QNX Fabric input to JavaScript — 2026-11-07

This bounded follow-up closes the raw Fabric JavaScript-delivery gap left by
[PR46's native-interception probe](../validation/qt-input-lifecycle-2026-11-07.md).
It does not add a recognizer, native public API or production input implementation.
Base `48e37f7550b4244f8a7936c01af75419e1fec416`; source
`482ce0622d5175054fdffd9347e0d99dba5bde81`. The
[machine-readable receipt](pi400-input-js-2026-11-07.json) pins the lock and artifacts.

## Change and observable proof

The bytecode fixture now registers a real Fabric JavaScript handler and retains
its received events. The native observer normally returns false so RN's actual
EventBeat/runtime scheduling delivers events instead of consuming them. After
bounded event pumping, the probe asserts all12 callbacks in order and compares
identifier, target, pageX, timestamp and active-contact count with the native
payload observations. Existing decorated-target, terminal, cancellation, target
removal and reentrant mouse-release assertions still run.

An explicit fault control, `RNQNX_INPUT_INTERCEPT_TEST=1`, restores native-only
consumption. The native assertions still pass, but JavaScript receives nothing;
the probe must reject this at its JavaScript event-count assertion. The automated
host wrapper requires exit1 and that specific diagnostic, rejects a JS-success
marker and sanitizer diagnostics, and does not accept a missing fixture or crash.
The fault variable affects only this opt-in test executable.

## Reproduce

Use the existing documented full RN/Hermes/Qt graph:

```sh
cmake -S . -B build/macos-full-host-tests -DRNQNX_ENABLE_INPUT_LIFECYCLE=ON
cmake --build build/macos-full-host-tests --parallel 4
ctest --test-dir build/macos-full-host-tests --output-on-failure
# Repeat configure/build/CTest with OFF; input tests must be absent.
```

For the licensed full QNX graph, enable the same input option and set
`RNQNX_INPUT_TEST_HERMESC` to the pinned host compiler. Build
`rnqnx_input_lifecycle_probe`, deploy it and `input-lifecycle-setup.hbc` alongside
the existing validated Qt runtime, and use the Hello World runbook's QPA,
plugin/import/library environment. Set `RNQNX_INPUT_FIXTURE` to the target HBC.
Run once normally and once with `RNQNX_INPUT_INTERCEPT_TEST=1`, capturing each
exit status and marker under an external watchdog. The latter must fail exactly
at JS event count; a generic nonzero exit is insufficient. Do not evaluate source
in the lean QNX Hermes runtime.
