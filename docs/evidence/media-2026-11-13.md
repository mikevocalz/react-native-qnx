# Qt Multimedia and QtVideo on the Pi 400, November 13, 2026

Board: Raspberry Pi 400, QNX 8.0 (`uname`: `QNX qnxpi 8.0.0 2026/06/05`),
Qt core from `qt612-public-o2`, add-on in `/data/home/qnxuser/qt612-media`
(hashes in [`media/SHA256SUMS.txt`](media/SHA256SUMS.txt)). Source: branch
`feat/qt-video`. Built in the `qnx805-build` container with QNX SDP 8.0.5.

## What ran

1. **Probe** (`rnqnx_media_probe`, plain Qt, no React Native).
   - Backend: `Using Qt multimedia with FFmpeg version 8.0 LGPL version 2.1 or later`.
   - Software H.264 + AAC decode of the 480 x 270 test clip from a file path:
     170 frames in 7.0 s, position tracking wall clock. Same from
     `http://192.168.2.1:8765/rnqnx-test-clip.mp4`: 97 frames in 4.0 s.
   - Audio: `io-snd` was not running, so `QMediaDevices::audioOutputs()` was
     empty. I started `sudo io-snd -c /etc/system/config/sound/io_snd.conf`.
     `/dev/snd` then had `pcmC0D0p`; the only card is `bcm2711 pwm`, the 3.5 mm
     jack. Qt opened it (`Playback opened: "default" buffer_frames: 2112`); a
     3 s WAV played to `EndOfMedia` in 3.0 s. Whether it is audible has not
     been confirmed by ear.
   - Bad URL: `error=1 Could not open file`, `InvalidMedia`.
2. **React Native gallery** (`org.rnqnx.mediaproof`, a copy of the gallery with
   its app id changed so it could not collide with other running copies, and
   with the Media page as the start page and logging added; neither change is
   in the PR). Events from `QtVideo` reached JavaScript:
   `load {duration:8,width:480,height:270}`, `seek {currentTime:5.085,seekTime:5}`
   after `seek(5)`, `pause()` and `play()` through the ref, `end`, and after
   switching the source to a dead URL `error {message:"Could not open file",code:1}`
   (FFmpeg: `Connection refused`). The audio output opened from inside the app
   (`Playback opened: "default"`).
3. Screenshots (`--screenshot`, the app's own window):
   [`gallery-media-page-playing.png`](media/gallery-media-page-playing.png) shows
   the video frame in the Qt Quick scene graph with the native control bar
   (pause, time, scrubber, volume, fullscreen) and the React status line
   `playing 0.5 s - 480x270, 8.0 s`;
   [`gallery-advanced-video-card.png`](media/gallery-advanced-video-card.png)
   shows the Video card in the Advanced tab.

## https (later the same day)

FFmpeg was rebuilt with the SDP's OpenSSL 3 (`libavformat.so.62` now needs
`libssl.so.3` and `libcrypto.so.3`). The probe played
`https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4`
(960 x 540 H.264 + AAC, 5.06 s): 143 frames in 5.0 s, position tracking the
clock, with the certificate checked against the board's `/etc/ssl` store. A
first https build failed on the board with `unknown symbol: ff_udp_set_remote_addr`
(the `udp` protocol was not enabled) and a second played nothing because
`http.o` was stale after the reconfigure; both are fixed in `build-ffmpeg.sh`
(`udp` added, libavformat objects rebuilt) and the add-on on the board is the
working build.
