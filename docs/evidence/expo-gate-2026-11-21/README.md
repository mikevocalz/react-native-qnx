# Expo gate closure audit, 2026-11-21

Base: main `4a4c4818c37c8107f5c92471ed024f61243627cf`. Every result below is **host** (macOS arm64, Darwin 27.0.0, Node 26.13.0, pnpm 12.21.0, `pnpm install --frozen-lockfile` in a fresh clone). Nothing ran on the QNX VM, a Pi 400 or the release board. The `expo` gate in `docs/releases/v1-readiness.json` stays `pending`.

## Why the gate stays pending

The acceptance sentence needs a prebuilt runner downloaded on a clean host, Fast Refresh on a device, and a standalone package launched on a device, recorded end to end. Three facts block that, and none of them is a host or VM matter:

- `gh release list --repo mikevocalz/react-native-qnx` returns no release. No runner archive or `rnqnx-runner-manifest.json` is published, so `runner fetch` has nothing to download. `runner-release.yml` attests an archive that a machine with a licensed SDP must build and upload to a draft release by hand (ADR-0018). That is an owner or release-board step.
- No board is available: the Pi 400 display is under repair and no release board has been provided. The QNX VM has no qualified Qt/Hermes runner build for it and would not satisfy "the device" in the acceptance text.
- `apps/expo-router-example` contains only `.gitkeep`. The Router app that ships is `apps/component-gallery`. Creating the example would be a new app, which the frozen scope does not allow this lane to add without an owner decision.

## What the owner or the board must supply

1. A runner build on a licensed-SDP machine, uploaded to a draft release and attested with `runner-release.yml`, then a download-and-verify run from a clean host.
2. A decision on `apps/expo-router-example`: create it from `template/qnx-router` (or promote `component-gallery`), under the frozen-scope rule.
3. Item 6: either a test that runs Expo CLI's own `expo start` against a QNX development build, or an ADR that narrows the gate text to `project start`. This lane did not loosen the gate.
4. A board (not the Pi 400 while its display is under repair) for Fast Refresh, the standalone package launch and the end-to-end recording.

## Files

Every log in this directory comes from a command run in the fresh clone. `SHA256SUMS` lists each file and `shasum -a 256 -c SHA256SUMS` resolves every entry. `environment.txt` records tool versions and the base commit.

Reproduce, from the repository root after `pnpm install --frozen-lockfile` with Watchman off PATH:

```sh
node tests/js/<name>.test.mjs
node scripts/expo-sdk58-support.mjs --check
node scripts/expo-capability-table.mjs --check
node scripts/validate-qnx-expo-modules.mjs
node scripts/validate-qnx-expo-autolinking.mjs
node scripts/validate-expo-modules2.mjs
cmake -S tests/native/runtime-preflight -B <build> -G Ninja -DCMAKE_PREFIX_PATH=<Qt6>
cmake --build <build> && ctest --test-dir <build> --output-on-failure
```

An earlier attempt to call the `validate:*` pnpm scripts through a shell variable failed with exit 127 (`command not found`); that was a quoting error in the runner shell, not a repository failure. The scripts were then run directly with node, as listed above.
