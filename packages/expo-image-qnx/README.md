# @rn-qnx/expo-image-qnx

Registers what [`expo-image`](https://docs.expo.dev/versions/latest/sdk/image/)
58 needs from the native side on QNX: the `ExpoImage` native module and the
view config of its `ExpoImage` view. Add both packages to an app:

```json
"dependencies": {
  "expo-image": "58.0.18",
  "@rn-qnx/expo-image-qnx": "workspace:*"
}
```

`project prepare-native` records the package in `native-app.json` as an
`expoModules` entry, as it does for `@rn-qnx/expo-constants-qnx`. The view
itself is the renderer's Fabric component `ViewManagerAdapter_ExpoImage`,
built with `RNQNX_ENABLE_QT_EXPO_IMAGE` (on by default in a consumer app
build). Without that option the JavaScript loads and the view is an unknown
component.

## What works

The view is `ExpoImageItem` (`vnext/src/views/qt/image`), a `QQuickPaintedItem`
that loads, decodes and paints the picture with `QPainter`. It does not use
`QtQuick.Effects` or any shader, because the Pi's Qt runtime ships neither.

| expo-image API                                                                                        | QNX                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source` (object or array)                                                                            | `uri` with its `headers` and `cacheKey`; with several entries, the smallest `width` that covers the view, else the largest; `blurhash` and `thumbhash` sources                                                                                                                                                                                                                                |
| `headers`                                                                                             | sent on http(s) requests; the memory and disk cache key includes them (or the `cacheKey`)                                                                                                                                                                                                                                                                                                     |
| `placeholder`, `placeholderContentFit`                                                                | `uri`, `blurhash` or `thumbhash`; shown until the image is ready, then transitioned away                                                                                                                                                                                                                                                                                                      |
| `contentFit`                                                                                          | `cover`, `contain`, `fill`, `none` (natural size), `scale-down`                                                                                                                                                                                                                                                                                                                               |
| `contentPosition`                                                                                     | edge words, offsets in points and percentages, in object or string form                                                                                                                                                                                                                                                                                                                       |
| `transition`                                                                                          | `duration`, `timing`, and the effects `cross-dissolve` and `flip-from-top`, `-right`, `-bottom`, `-left`; `curl-up` and `curl-down` draw as a cross-dissolve and log one warning (expo-image documents them as iOS-only)                                                                                                                                                                      |
| `tintColor`, `blurRadius`                                                                             | yes, in `QPainter`; blur is a three-pass box blur on the CPU, not applied to placeholders                                                                                                                                                                                                                                                                                                     |
| `borderRadius` (and per-corner radii), `borderWidth`, `borderColor`                                   | the picture is clipped to the rounded shape                                                                                                                                                                                                                                                                                                                                                   |
| `cachePolicy`                                                                                         | `none`, `disk`, `memory`, `memory-disk`; the disk cache holds 128 MiB with least-recently-used eviction                                                                                                                                                                                                                                                                                       |
| `recyclingKey`                                                                                        | a changed key clears the old picture at once, with no transition                                                                                                                                                                                                                                                                                                                              |
| `allowDownscaling`                                                                                    | an image over twice the view in both dimensions decodes at the smallest size that still covers it; `onLoad` reports the original size                                                                                                                                                                                                                                                         |
| `autoplay`, animated GIF and WebP                                                                     | played with `QMovie` when the Qt build has the format plugin; `autoplay: false` shows the first frame                                                                                                                                                                                                                                                                                         |
| `onLoadStart`, `onProgress`, `onLoad`, `onError`, `onDisplay`                                         | `onProgress` carries bytes received and the total; `onLoad.cacheType` is `none`, `disk` or `memory`                                                                                                                                                                                                                                                                                           |
| `testID`, `nativeID`, `pointerEvents`, `hitSlop`, `accessibility*`                                    | `hitSlop` widens the touch area; `pointerEvents` `none` and `box-none` ignore touches; accessibility maps to Qt `Accessible` properties                                                                                                                                                                                                                                                       |
| `opacity`, `transform`, `onLayout`                                                                    | applied by the mounting layer and Fabric, as for any view                                                                                                                                                                                                                                                                                                                                     |
| `Image.prefetch`, `clearMemoryCache`, `clearDiskCache`, `getCachePathAsync`                           | forwarded to the renderer's `ImageLoader`, so they act on the cache the view reads; `getCachePathAsync` returns null for a key that is not on disk. `prefetch` resolves `false` as soon as one URL fails                                                                                                                                                                                      |
| `priority`                                                                                            | `low`, `normal` (the default) or `high`. Every view, `prefetch` and `loadAsync` load HTTP(S) images through one queue (`ImageFetchQueue`) that runs 6 loads at a time; waiting loads start highest priority first, and first come first served within a priority. Disk, memory and file sources do not wait                                                                                   |
| `enableLiveTextInteraction`                                                                           | accepted and ignored. expo-image marks it `@platform ios 16.0+` (Apple VisionKit Live Text); there is no equivalent on QNX                                                                                                                                                                                                                                                                    |
| `Image.loadAsync`, `useImage`                                                                         | decode a source (`uri` with `headers` and `cacheKey`, or a `blurhash:/` or `thumbhash:/` source) into an `ImageRef`; `maxWidth` and `maxHeight` scale it down (never up) keeping the aspect ratio, `tintColor` colors it; `onError` retry works through `useImage`. The first frame only: an animated image is not played from an `ImageRef`                                                  |
| `ImageRef` (`width`, `height`, `scale` 1, `mediaType`, `isAnimated` false, `release()`)               | a `SharedRef` of kind `image` that holds the decoded picture in the renderer. It works as `source` or `placeholder` of the view; after `release()` the view reports an error instead of showing it                                                                                                                                                                                            |
| `Image.generateBlurhashAsync`, `generateThumbhashAsync`                                               | encode a URL or an `ImageRef`; `numberOfComponents` is `[x, y]` or `{ width, height }` (1 to 9 each, `[4, 3]` when omitted, `null` when out of range). The picture is scaled to at most 100 px on its long side first. The encoders reproduce the reference JavaScript packages exactly on the test vectors (`tests/fixtures/image-hashes`)                                                   |
| `Image.writeToCacheAsync`, `readFromCacheAsync`                                                       | `writeToCacheAsync(file URI or ImageRef, cacheKey)` stores the picture's bytes (a PNG for an `ImageRef`) in the disk cache and the decoded picture in the memory cache under `cacheKey`; a source with that `cacheKey` then loads from them with no request. `readFromCacheAsync(cacheKey)` returns an `ImageRef`, or `null` when neither cache has the key                                   |
| `Image.configureCache`                                                                                | `maxDiskSize` (bytes, 0 means no limit), `maxMemoryCost` (bytes of decoded pictures) and `maxMemoryCount` (0 means no limit; the oldest inserted picture goes first). expo-image documents it as `@platform ios`; it is implemented here because the caches are the renderer's own                                                                                                            |
| `startAnimating`, `stopAnimating`, `lockResourceAsync`, `unlockResourceAsync`, `reloadAsync` on a ref | Fabric view commands (`Commands` in `ExpoImageNativeComponent.ts`). The function on the view ref calls `expo.dispatchViewCommand` (QNX polyfill), which calls React Native's `dispatchCommand`; the mounting layer runs the command on the `ExpoImageItem`. A locked view keeps its picture when `source` changes until `unlockResourceAsync`; `reloadAsync` loads again and ignores the lock |
| `imageLoaded` module event                                                                            | emitted for `loadAsync`, `readFromCacheAsync` and every picture the view loads, with `{ url, width, height }`; expo-observe subscribes to it                                                                                                                                                                                                                                                  |
